# eTraderBot v1 Spec

## Problem Statement

交易员希望把电力交易的数据、操作经验和决策方法交给 Bot，在能够验证结果、保留追溯依据并由人控制交易权限的前提下，逐步让 Bot 承担交易工作。

当前产品具备会话、Bot、技能、记忆、定时任务和通用工具集成，但尚未实现电力交易的数据契约、可追溯算法版本、业务风控、逐笔批准与范围授权、交易执行和算法学习验证闭环。单靠聊天记忆和技能修改，无法证明某个交易策略适用、经过验证或拥有执行权限。

## Solution

在现有 eTraderBot 壳的 Bot 内增加交易能力，覆盖售电公司、发电企业、独立储能三类主体，产品地区范围为上海、江苏（业务地点苏州）和山东。先在左侧选择或新建业务范围，再在该范围下创建中长期交易、现货交易、风控、复盘四种模板 Bot；同一业务范围集中管理 Bots 与接口。现货 Bot 内切换日前、日内、实时交易阶段；通用 Bot 同样归属当前业务范围，“全部 Bots”用于跨业务导航。

三类主体分别完成数据读取、指定算法运行、候选决策、风控、逐笔批准或范围授权、模拟执行、回执、复盘和学习。当前交付每类使用一个可执行且可重放的工程基线，并验证参数候选、约束对照与人工启用流程；真实策略改进结论需要另行取得数据验证。第一版以模拟接口交付完整流程，真实公司接口取得后单独联调。

每个 Bot 每天自动学习，也支持使用者主动触发；创建 Bot 时可设置学习时间，此后可通过对话修改。学习利用聊天、文件、已授权操作记录和历史数据，以交易员经验为基线，也允许提出不同参数候选。候选经过验证后由人批准启用；交易执行继续受独立批准或范围授权约束。

## V1.1 工作区隔离修订（2026-11-04，首批已实施）

使用者已确认采用[交易工作区与通用工作区分离](../adr/0004-trading-general-workspace-isolation.md)：四类交易模板归属交易业务工作区，普通 Bot 归属独立通用工作区，只能按明确授权读取指定交易资料，不能修改交易资源。本 Spec 中关于普通 Bot 与交易 Bot 共处当前业务范围的描述保留为 V1 实现背景，当前行为以该决议为准。首批已实现工作区类型、后端与数据库约束、工具资源隔离、同一使用者名下按记录授权的只读读取及已确认历史数据迁移。具体范围、迁移和限制见 [V1.1 工作区隔离实施说明](../implementation/eTraderBot-v1.1-workspace-isolation.md)，验收统计见实施及验收记录。

## 业务主管补充（2026-11-04）

每个交易业务工作区固定一位主管 Bot，协调现有四类专业 Bot 的任务分配、结果汇总与进度统计。主管身份不包含交易角色、算法启用、交易批准或执行资格；任务分配不能跨业务或继承批准。任务与运行复用现有看板和队列。完成率按持久化任务状态计算，模型运行结束或取消任务不自动计为完成。Web/Electron 与移动入口共用后端边界。实现与限制见[业务主管说明](../implementation/eTraderBot-business-supervisor.md)。此项先于固定版本经验交接实施。

## 固定版本经验交接 MVP（2026-11-05，后端与 Web 已实施）

依照[固定版本导入决议](../adr/0005-versioned-experience-handoff.md)，后端已实现用户选中的总结、原生记忆和文本 Skill 的版本化交接包、来源与适用条件、导入预览、原子确认和历史。支持同一用户拥有的工作区间交接；服务端重查源/目标权限。目标副本独立，Skill 默认待启用，后续版本不自动覆盖，重复导入幂等，冲突要求改名或显式跳过。凭据、模板/角色权限、算法启用及交易授权均不迁移。包撤销禁止新导入，已授权副本和历史保留，源 Bot 删除不删除交接记录。Web/Electron 共用的选择、预览、确认及历史入口已接入，来源标签、过期预览恢复和错误语言切换已有浏览器回归。权限撤销、凭据/交易授权不转移与相同 confirm 幂等通过的是隔离 RPC/PostgreSQL 测试，浏览器 HTTP 重试仍未验证。已有真实模型读取导入 Skill 的记录，但不代表模型质量提升；移动端与原生壳未验收，外部记忆导入暂安全拒绝。具体接口、测试和限制见[交接 MVP 后端记录](../implementation/eTraderBot-experience-handoff.md)及[Claude 接入说明](../integration/eTraderBot-experience-handoff-api.md)。

## 当前范围调整（2026-11-04）

使用者确认现阶段只有生成数据、尚无真实公司接口，并明确搁置论文算法实现。本轮完成可独立验证的模拟执行生命周期与现有学习流程：部分成交、提交超时核对、拒单、撤单及撤单超时、额度占用／核销／释放。保留三类工程基线及参数候选流程；论文选型、算法复现、真实数据上的学习效果与收益验证均标记为搁置，不计为已完成。下文涉及论文与改进效果的故事保留为后续目标。

真实公司接口不是内部模拟流程的前置条件。真实模型语义评价、真实接口联调和原生设备验收仍单独记录；测试全部通过仅表示所列模拟功能通过，不能据此宣称完整实盘产品或策略效果通过。逐项结果见 [V01–V14 验收记录](../implementation/eTraderBot-v1-acceptance.md)。

## User Stories

以下采用“作为某类使用者，我希望获得某项能力，以便取得某种结果”的用户故事结构。

1. 作为售电交易员，我希望 Bot 分析购电、合同组合和敞口，以便形成可检查的调整方案。
2. 作为发电交易员，我希望 Bot 在可发能力和成本约束下生成量价申报候选，以便辅助申报决策。
3. 作为储能交易员，我希望 Bot 根据电量、功率、效率等约束生成充放电与报价候选，以便形成可执行计划。
4. 作为使用者，我希望为业务选择主体、账户、资产和地区，以便让数据、规则和授权应用于正确对象。
5. 作为使用者，我希望地区配置能够表达上海、江苏苏州和山东，以便分别接入适用的业务配置。
6. 作为交易员，我希望看到数据来源、时间和适用规则，以便判断结果是否适用于当前任务。
7. 作为交易员，我希望数据缺失、过期或接口未配置时得到明确反馈，以便补齐资料后继续处理。
8. 作为交易员，我希望清楚区分合成数据与真实数据，以便正确理解验证结果。
9. 作为使用者，我希望第一版用模拟接口跑通完整业务，以便在真实接口准备期间验证产品。
10. 作为接入人员，我希望模拟与真实适配器遵循同一交易契约，以便更换数据和执行来源时保留业务逻辑。
11. 作为交易员，我希望使用中长期 Bot 处理相应合同与敞口任务，以便持续协作。
12. 作为交易员，我希望在同一现货 Bot 下切换日前、日内、实时任务，以便按场景使用相应能力。
13. 作为交易员，我希望风控 Bot 检查并解释风险和拒绝原因，以便及时调整方案。
14. 作为交易员，我希望复盘 Bot 关联决策、执行和反馈，以便形成有依据的复盘。
15. 作为交易员，我希望角色协作时保留业务范围和记录关联，以便避免把其他账户的结果用于当前业务。
16. 作为交易员，我希望每次调用固定的算法版本，以便知道候选决策由什么方法产生。
17. 作为审核人，我希望查看算法的输入要求、适用范围、约束和验证证据，以便判断是否启用。
18. 作为交易员，我希望使用固定输入快照重放算法，以便核对结果和调查异常。
19. 作为使用者，我希望算法逻辑或参数变化产生新版本，以便保留旧结果的含义。
20. 作为交易员，我希望 Bot 能参考论文和经验形成算法草稿，以便持续探索改进。
21. 作为交易员，我希望 Bot 展示候选决策的结构化数值和解释，以便分别核对计算与判断依据。
22. 作为使用者，我希望在 Bot 的初始业务配置中确定默认每日学习时间，并在其学习页调整，以便学习安排符合自己的工作节奏。
23. 作为使用者，我希望通过与 Bot 对话修改学习时间，以便方便地调整计划。
24. 作为使用者，我希望看到学习计划的时间、时区和下次执行时间，以便确认修改已经生效。
25. 作为使用者，我希望每日学习自动执行，以便经验能持续积累。
26. 作为使用者，我希望随时手动启动学习，以便新资料到达后及时处理。
27. 作为交易员，我希望聊天中的解释与反馈可以成为学习资料，以便 Bot 学到决策背景。
28. 作为交易员，我希望上传文件可以进入学习过程，以便复用已有规则、记录和分析材料。
29. 作为交易员，我希望已授权的操作记录可以进入学习过程，以便 Bot 学习实际工作方法。
30. 作为交易员，我希望历史数据可以进入学习过程，以便验证经验与候选算法。
31. 作为交易员，我希望学习产物保留资料来源，以便检查经验是否可靠并追溯其业务范围。
32. 作为交易员，我希望 Bot 以人工经验或现有算法作为比较基线，以便理解候选的变化。
33. 作为交易员，我希望 Bot 可以提出与我不同的策略，以便发现值得评估的替代方案。
34. 作为审核人，我希望不同策略展示依据、约束和对比验证结果，以便作出有证据的批准。
35. 作为使用者，我希望证据不足的改进保持为草稿，以便避免把未经验证的猜测当成改进。
36. 作为使用者，我希望没有新资料时也能看到学习结果或说明，以便知道任务确实执行过。
37. 作为使用者，我希望学习失败能够查看原因并重试，以便恢复工作。
38. 作为使用者，我希望重复触发学习时能知道任务是复用还是新建，以便避免重复操作。
39. 作为算法审批人，我希望批准明确的算法版本及验证报告，以便批准效力对应确定的内容。
40. 作为交易授权人，我希望逐笔批准具体交易意图，以便保持每次执行的控制权。
41. 作为交易授权人，我希望授权 Bot 在明确范围内自主执行，以便在建立信任后减少逐笔操作。
42. 作为交易授权人，我希望授权绑定主体、账户或资产、市场、业务、算法版本和期限，以便约束执行范围。
43. 作为交易授权人，我希望同时设置单笔与累计限额，以便控制授权期间的总风险。
44. 作为交易授权人，我希望随时撤销范围授权，以便停止后续新增提交。
45. 作为个人使用者，我希望可以同时承担算法审批和交易授权职责，以便独立使用产品。
46. 作为团队使用者，我希望把两类审批权限分配给不同的人，以便按实际职责协作。
47. 作为交易员，我希望未经授权的算法版本不能执行交易，以便学习改动不会自动影响正在使用的策略。
48. 作为交易授权人，我希望修改交易意图后不能沿用原批准，以便批准与实际执行保持一致。
49. 作为交易员，我希望超范围、过期和撤销后的提交被明确拒绝，以便及时请求新的授权。
50. 作为交易员，我希望影子运行只生成候选，以便观察 Bot 而不改变交易状态。
51. 作为交易员，我希望模拟执行生成明确标识的状态和回执，以便验证后续流程。
52. 作为交易员，我希望提交超时后可以核对状态，以便避免重复提交。
53. 作为交易员，我希望授权撤销后仍能跟踪已提交操作，以便核对后续结果。
54. 作为使用者，我希望模拟权限与真实执行权限明确区分，以便模拟操作不能误用于真实交易。
55. 作为使用者，我希望论文与通用交易知识可以共享，以便多个 Bot 复用公共方法。
56. 作为使用者，我希望业务原始数据和专有策略默认按主体、账户隔离，以便控制业务资料的使用范围。
57. 作为使用者，我希望自己选择可以共享的经验及共享对象，以便有意识地复用知识。
58. 作为使用者，我希望从业务资料提炼的经验继承其访问范围，以便经验总结不会扩大资料的读取权限。
59. 作为审核人，我希望查看数据、版本、风控、批准、执行和学习的完整关联记录，以便复盘与调查。
60. 作为使用者，我希望在 Web、桌面和适用移动交互中查看相同的业务状态，以便跨端继续工作。
61. 作为使用者，我希望知道哪些操作资料必须从支持录屏或采集的端取得，以便选择合适的入口。
62. 作为维护者，我希望使用合成数据离线验证契约和交易行为，以便稳定地发现回归。
63. 作为使用者，我希望真实模型学习的效果、错误和费用单独呈现，以便评估实际运行能力。
64. 作为使用者，我希望看到仍未接通的真实接口和未核实的市场规则，以便区分已完成能力与外部依赖。
65. 作为使用者，我希望在“新建 Bot”时直接选择四种交易模板，以便创建后即可配置对应业务，不必再手动指定交易角色。
66. 作为使用者，我希望在同一个 Bot 内切换聊天、交易或检查、学习，以便保留助手和业务上下文。
67. 作为使用者，我希望多个角色 Bot 可以连接同一授权业务范围，以便协作查看相同证据，并分别管理各自的学习计划。
68. 作为审批人，我希望在 Bot 工作区处理分配给自己的人工审批，同时不因此授予该 Bot 读取或交易权限。

69. 作为使用者，我希望先在明显的业务范围选择器中选择主体、账户及地区，再进入对应 Bots，以免在不同业务间混用配置。
70. 作为使用者，我希望同一业务范围下集中显示四种模板 Bot，并在创建时自动归入当前范围，以便协同处理同一业务。
71. 作为接入人员，我希望在业务范围旁直接进入接口设置，并配置多个行情、预测、持仓资产、市场规则、执行和回执接口，以便不同业务采用不同服务。
72. 作为接入人员，我希望优先配置普通 HTTP 数据 API，同时可以选择已有 MCP 连接，以便复用不同系统的接入方式。
73. 作为使用者，我希望明确区分已保存配置、已验证连通、Bot 工具访问和交易授权，以免误认为填入地址即可执行交易。
74. 作为使用者，我希望交易页和学习页各自显示交易证据与学习计划、资料及报告，而不用反复配置同一业务范围。

75. 作为使用者，我希望在 Bot 列表及会话中看到其所属业务范围的名称标签，以便在全部 Bots 或多个业务范围之间辨认归属。
76. 作为使用者，我希望业务范围直接替代私人空间，统一管理该业务的 Bots、群聊、资料、接口和学习记录，并保留原有聊天与审批历史。

## Bot 模板与页面结构（2026-11-04 修订）

主路径：**左侧选择／新建业务范围 → 新建 Bot → 选择模板并命名 → 聊天 / 交易或检查 / 学习**。左侧业务范围选择器始终位于 Bot 列表上方；“+”菜单也提供新建业务范围。选定范围后，显示该范围的 Bots，并提供接口设置入口。全局账号菜单不再提供独立交易入口；旧 Web `/app/trading` 书签回到 Bot 列表。普通 Bot 保持通用聊天功能。

| 模板 | Bot 内业务页 | Bot 工具权限 |
| --- | --- | --- |
| 中长期交易 | 交易：中长期合同与敞口 | 仅已绑定中长期范围内的分析、候选准备与有授权的模拟执行 |
| 现货交易 | 交易：日前、日内、实时 | 仅已绑定现货范围内的分析、候选准备与有授权的模拟执行 |
| 风控 | 风险检查：敞口、限额和批准依据 | 查询业务证据；不能准备或执行订单 |
| 复盘 | 交易复盘：决策、回执与审计记录 | 查询业务证据；不能准备或执行订单 |

- 模板角色独立于 Bot 名称、提示词和普通设置持久化；修改名称或指令不能改变权限。模板提供默认角色指令，但权限最终由后端检查。在选定业务范围创建模板时，后端原子建立适用交易场景的绑定与默认学习计划；不产生算法批准、交易授权或模型介绍任务。
- 业务范围保存名称、主体、账户、资产、地区、市场、产品、模拟环境和两类审批人；不包含交易阶段。交易场景在该范围内进一步固定阶段。中长期模板绑定中长期场景，现货模板绑定日前／日内／实时，风控和复盘模板绑定全部四个阶段；同一范围的相同阶段由后续 Bots 复用。
- 业务范围可以先于 Bot 创建。创建模板 Bot 时，Bot、场景、角色绑定和学习计划在同一事务完成；失败不留下半创建 Bot。每个 Bot 通过 `spaceId` 唯一归属一个业务范围，通用 Bot 也遵循相同规则；跨业务复用角色时创建独立模板实例，不共享同一个 Bot。范围、场景和 Bot 权限分别校验，不能借加入范围把只读模板升级为交易角色。
- 每个已连接范围默认建立每日 `02:00 / Asia/Shanghai` 学习计划，可在当前 Bot 的“学习”页修改时间、时区、启停和基线，或主动启动，也保留通过 Bot 对话修改的能力。学习页仅展示当前 Bot 的计划、运行与报告；同一授权范围的学习资料按既有范围规则管理。
- 业务页保留固定输入、算法版本、候选、逐笔批准、范围授权、模拟回执与审计。人直接发起的分析、准备与模拟执行保留人工执行主体；Bot 工具产生的候选与执行保留 Bot 主体，不因移动页面改变归属。
- Bot 的交易权限与使用者的审批资格分开。具有审批资格的人仍可在业务页明确批准、退役或撤销；风控和复盘 Bot 的只读工具权限不随这些人工操作改变。分配给使用者但未向当前 Bot 开放的范围标明“人工审批 · 此 Bot 无权访问该业务范围”，不得自动绑定或向模型提供资料。
- 断开当前 Bot 与交易场景的连接后，暂停对应学习计划并拒绝后续 Bot 在该场景交易；保留业务证据、回执和审计。其他 Bot 在该范围的连接不受影响。创建或复制模板均不继承交易授权。
- Web/桌面在 Bot 会话壳内切换页面，保留 Bot 列表与中英切换；语言切换保留填写内容，刷新恢复当前业务或学习页。移动端复用原生业务列表与切换，创建 Bot 时直接显示当前业务归属，从 Bot 资料进入交易与学习；可以先新建空业务范围，交易字段、接口和完整资料管理暂由 Web 配置，未配置时明确提示且不允许创建交易模板。

### Bot 业务归属标签

- Web／桌面在 Bot 列表名称下和会话顶部显示唯一业务范围名称；“全部 Bots”与单业务视图均保留标签，长名称省略并保留完整提示。
- 标签以 Bot 的 `spaceId` 和使用者有权访问的 Space 名称为准，覆盖普通 Bot 与交易模板。不依赖是否绑定交易场景；解除场景绑定不会改变 Bot 的业务归属。
- 名称不随界面语言翻译，只有未命名的原默认 Personal 显示本地化“默认业务范围”。重命名后，选择器、Bot 标签和业务配置沿用同一 Space 名称。
- 移动端在 Bot 资料页显示同一归属。没有合法归属数据时不根据当前筛选项猜测。

### 业务范围与接口配置

- **一个业务范围就是一个 Space。** 产品不再并列提供私人空间和业务范围。复用 Space 的成员、加密、聊天、文件与记忆隔离；`TradingWorkspace` 仅作为该 Space 的唯一交易配置扩展，内部标识与既有 RPC 路径保留。
- “新建业务范围”原子创建 Space、所有者成员、默认记忆与业务配置，初始两类审批人为创建者；不隐式拉入其他业务的成员。已有空 Space 可补充交易配置，审批人必须已是该 Space 的成员。同一 Space 不能配置第二个账户／主体／审批策略。
- 选择器列出有权访问的全部业务范围，包括尚未配置交易字段的既有 Space；切换时加载目标 Space 的 bootstrap 并重建会话上下文，RPC、记忆和接口随之切换。选择和“全部 Bots”视图可在刷新后恢复。
- “全部 Bots”汇总各业务的导航，打开 Bot 时切到其实际所属业务，不合并任何数据或授权。新建 Bot 归属当前活动业务；群聊和普通 Bot 也保留在该业务列表中。
- 交易页按阶段展示候选、版本、批准、授权、回执和审计；学习页只展示当前 Bot、当前阶段的计划、资料和报告。跨业务复用模板创建新的实例；资料共享必须显式选择，不自动继承凭据、记忆、批准或额度。
- 既有单业务 Space 就地升级，保留 Space／Bot／Desk／配置 ID、聊天、加密内容、算法、批准、意图、回执及审计。原 Personal 名称可采用已有业务配置名称，其他自定义名称保留。
- 如果旧数据库存在一个 Space 内多套业务配置，迁移必须原子拒绝并保留全部旧记录，等待明确分配历史与数据；不得根据首条配置自动迁移聊天、复制审批或重新加密覆盖证据。该异常需要单独迁移方案，不能声称已自动处理。
- 接口按用途配置多个条目：行情、预测、持仓与资产、规则、交易执行、回执、其他数据。HTTP 支持 GET／POST、URL、查询参数、POST 请求体，以及无认证、Bearer、请求头 API key、查询参数 API key。敏感值进入独立密钥字段，由现有 SecretStore 保存，返回值仅显示是否已配置；编辑留空保留已有密钥。
- 原有通用技能／连接的 `allSpaces` 或指定 Space 授权继续有效；已有全局可用项会出现在新业务中，仍可在“可用于”中收窄或显式共享。业务专用接口凭据与学习经验不采用该全局机制。
- MCP 仅选择当前所有者在该 Space 可用的已有连接；关联业务范围不会自动分配 Bot 工具权限，更不会产生交易授权。HTTP 和 MCP 可在同一业务范围并存。
- 配置仅由范围所有者编辑，采用修订号防止并发覆盖。审批人可以处理分配的交易审批，无须创建 Bot，但不能读取或修改接口密钥配置。
- **本轮交付边界：配置管理。** 保存后明确标记“已配置 · 未验证连通”。本轮不执行外部 HTTP 请求，不把普通 API 响应自动映射为交易快照，不自动调度数据采集，也不启动真实交易。外部适配器后续按已有数据／执行契约实现连通验证、字段映射、来源时效和失败反馈；直到这些通过前，现有交易运行继续明确使用合成数据。

## Implementation Decisions

本节将已确认范围转为工程契约。使用者已确认按此 spec 开始实施；下列约定是验收要求，尚未表示全部已经实现。

1. **复用现有壳。** 使用既有 Bot、会话、技能、routine、Task/Run、认证身份、MCP 工具集成和审批界面。新增交易业务能力，不引入替代壳的第二套编排内核。
2. **集中交易行为。** 交易模块提供同一套对外接口，承担数据访问、算法与验证、交易授权、执行状态和审计。MCP、界面和后台任务通过此接口访问，不能各自实现一套批准或额度逻辑。数据来源与执行适配器可以替换，业务契约保持一致。
3. **可信上下文。** 每次操作使用服务端认证得到的使用者、Space、Bot/任务归属和业务场景，检查其可访问的主体、账户或资产、市场、业务及环境。接口不得相信模型参数中的“审批人”“已批准”或自行声明的角色。
4. **主体和地区。** 业务对象表达三类主体及其账户、资产、地区和适用品种。苏州作为江苏内的业务地点记录。具体参与资格、时刻表、限价、考核与精度来自有来源的规则版本，不固化虚构的统一省参。
5. **数据契约。** 输入快照固定内容、来源、时间窗口、数据截止时间、业务范围、规则版本和单位。接口缺失、必填数据缺失、过期或规则未配置必须返回可区分结果，不能生成替代数字。合成数据全程保留标记。
6. **三类决策产物。** 售电产物表达购电或合同调整候选及敞口变化；发电产物表达量价申报及约束结果；储能产物表达充放电、报价和状态轨迹。每类最少提供一个实际计算的算法，不以自由文本或人工表透传完成验收。
7. **可复查的版本。** 算法版本固定代码、参数、模型产物、适用条件及必要运行配置；运行关联固定输入快照与规则版本。决策逻辑或参数改变产生新版本，不能覆盖旧版本。已批准版本不能指向随时可改写的工作文件或技能内容。
8. **版本状态。** 草稿形成后可进入验证；满足验证及复盘要求的版本进入待批准；有权限的人明确批准后成为已批准；退役后禁止新增交易使用。验证状态单独表达未完成、通过、失败、证据不足，避免把“任务完成”等同于“验证通过”。
9. **学习能力。** 学习可提炼记忆和经验、形成技能或算法草稿，自动执行验证与比较。允许与交易员不同的方案，但必须保留依据。任何影响交易决策的技能、规则、参数或代码变更，都受算法版本和启用批准约束。
10. **学习触发。** 每个 Bot 的已绑定业务范围保存每日时间、时区、是否启用和下一次触发时间。初次配置建立默认安排；授权使用者可在学习页或对话中修改，成功后显示新安排。手动触发与每日触发进入同一学习流程，不隐含任何交易批准。
11. **学习去重及恢复。** 同一 Bot、输入范围和验证配置的相同运行请求复用正在处理的任务；新资料可以形成后续任务。停机恢复后合并补一次遗漏窗口。失败显示原因，可重试；没有新资料或充分证据时允许只产出报告，不强制生成或发布新版本。并发限制作用于对应资源，不将所有 Bot 串行处理。
12. **验证证据。** 比较候选、人工经验或现有算法时使用一致的数据窗口和适用规则，分别记录训练、调参与评价数据。报告包含基线、目标、硬约束、业务指标、适用范围、失效场景和结论。未设评价目标、资料不足或评价出错不能显示优于人工或验证通过。
13. **两项审批权限。** 算法启用批准与交易批准/范围授权分别检查，可由同一人兼任，也可分配给不同人。风控 Bot 只能提供检查与升级意见。Space 管理权限、能打开审批卡、通用“始终允许”或模型文本都不自动取得交易审批资格。
14. **逐笔批准契约。** 待批准交易意图固定主体、账户或资产、市场与业务、环境、算法及规则版本、输入依据和具体交易参数。服务端保存不可变意图及摘要，批准绑定其标识、内容、有效期和审批人。改变任何受批准字段须形成新意图并重新申请。重复执行同一请求返回原状态，不再次提交。
15. **范围授权契约。** 授权固定可操作主体、账户或资产、市场与业务、环境、算法版本、期限、单笔及累计限额、审批人与撤销状态。每次新增提交重新核验，启用新算法不会自动继承旧授权。更换版本、扩大范围或放宽限额需有权限的人重新授权。
16. **额度与并发。** 准入校验、授权状态检查、额度占用和提交登记采用持久化原子协调；并发请求不能使用同一份剩余额度。计量单位、累计窗口及核销规则来自明确的授权/业务配置；无法计算占用时拒绝提交。根据确定回执核销或释放占用。当前模拟以逐行绝对限价乘电量计算毛名义金额，`usedCny` 表示累计确认成交的核销额，`reservedCny` 表示未确定订单的占用额；已用加占用加新意图不得超过累计上限。按每行累计成交计算并取六位小数，避免分批成交重复取整。
17. **执行状态。** 提交登记后区分待提交、待回执、结果不确定和有明确依据的结果；结果状态保留外部状态及相关回执。超时或断连进入待核对状态，不能直接等同于拒绝或再次提交。模拟执行提供可重复的状态与回执契约，真实适配器随后接入相同契约。当前内置场景由范围所有者经身份确认配置，新订单固定场景；支持立即成交、部分成交、提交超时、拒单、挂单、撤单超时、场所持续不可用。首次回执不可改写，后续按递增序号追加；查询无副作用，核对显式携带已见序号，过时请求只返回当前记录。场所持续不可用保持不确定和占用，不能因次数或超时自动释放。
18. **授权撤销与已提交操作。** 撤销、过期、范围不匹配或关键校验失败阻止新增提交；已提交操作继续跟踪。撤销授权不等于交易撤单，撤单是另外的受授权交易操作。历史批准、版本、请求与回执保留关联。人工撤单由指定交易授权人经身份确认发起；Bot 仅能对自己提交的订单，在原限额授权仍有效且明确授予 `allowCancellation` 时撤单（默认关闭）。学习运行不能执行交易、核对或撤单。取消请求与核对串行协调，终态不回退，已确认成交不撤销核销。
19. **环境隔离。** 回测、影子运行、模拟执行、真实执行分别记录。影子运行只保存候选；模拟执行生成模拟状态和回执。模拟来源、批准或回执不能作为真实执行的资格；真实接口未接通时明确显示未接通。
20. **资料与共享契约。** 资料记录来源、所属范围和访问条件；从业务资料生成的经验继承原访问边界。论文与通用交易知识允许复用；业务数据和专有策略默认按主体、账户隔离。显式共享限定内容、对象与使用范围，保留操作记录，不把经验总结自动视为公开知识。
21. **角色与场景权限。** 四 Bot 角色沿用各自职责；现货仍为一个角色，承载不同场景。工具分配可以复用已有按 Bot/MCP 的控制，但场景、对象、操作与额度必须在交易接口执行时核验，技能说明或 routine 清单本身不作为权限证明。
22. **持久化约定。** 复用既有身份和任务记录，新增业务上下文、资料/快照、算法版本、验证、候选决策、批准、范围授权及额度占用、执行回执和审计记录。关键记录建立关联及幂等约束；数据库迁移保持新旧应用短时间并行的兼容性。具体物理表和索引在契约实施时确定。
23. **运行限制。** 生成代码和训练/验证在受限环境运行，不能访问真实交易写权限或生产凭据。外部模型、数据与计算来源保持可配置，业务契约不绑定特定服务商。敏感凭据通过已有连接设置管理。
24. **跨端行为。** 共享契约、交易校验和状态由后端及共享模块负责。Web 与桌面复用相应交互，移动端覆盖适用的查询与批准等行为；本机录屏等采集由具备能力的端完成，其他端查看已授权记录。
25. **交付完整性。** 第一版覆盖三类主体各自的完整闭环，以及每日/手动学习和两种交易批准方式。实施顺序沿用 M0–M5；先贯通一类再扩展其余两类，最终必须全部通过。真实接口和效果验证单独报告。

## Testing Decisions

1. **主测试入口，已随实施批准确认。** 以 Bot 实际调用的交易工具接口作为主要测试入口，通过认证上下文和明确命令执行数据、算法、学习、批准、授权、提交与查询。接口返回的结构化结果、持久状态、模拟回执及审计关联构成断言依据。MCP、界面和后台触发共用同一交易接口，避免对每层内部实现重复测试。工具绑定完成前，先通过同一应用服务的认证 RPC 入口验证现有切片，不将它等同于 Bot 端到端验收。
2. **测试外部行为。** 好的测试说明在给定数据、身份、授权和操作下，使用者得到什么结果、是否产生提交、权限/额度/状态如何变化；不依赖内部函数调用次数、私有方法或提示词的精确措辞。仅在无法从接口验证的计算或事务性质上增加必要的内部测试。
3. **离线与可控依赖。** 主要验收使用合成数据、模拟时钟、可替换的数据与执行适配器以及可观察的受限算法运行。多数行为测试不要求外部网络或付费模型；真实模型的学习端到端检查独立运行，费用、错误和效果单独记录。
4. **数据与算法。** 三类主体分别检查可执行决策、数值约束、来源、固定版本重放和非法输入；修改参数、规则或数据后不能把旧证据视为覆盖新结果。明确训练/评价数据切分；无结果和证据不足不能通过。
5. **批准与授权。** 检查错误审批人、修改意图、换版本、跨主体/账户/资产、市场业务不匹配、过期、撤销、单笔/累计超额及模拟凭据用于真实执行。校验拒绝原因和未产生交易副作用，覆盖并发额度争用。
6. **提交与恢复。** 通过模拟执行接口验证请求重试幂等、结果不确定时状态核对、回执核销和授权撤销后的行为；区分停止新增提交与继续跟踪已提交操作。
7. **学习与共享。** 验证四类资料来源、每日/手动触发、创建和对话修改安排、重复运行与停机恢复、没有新资料、学习失败和提出不同策略的情形。验证未经启用批准不能改变交易策略，派生经验不能扩大访问范围，显式共享只开放指定内容。
8. **现有测试先例。** MCP connector 和连接流程测试提供工具发现、调用及分配权限的先例；审批 effect/replay 测试提供意图绑定与恢复的先例；routine 调度、运行历史和 coalescing 测试提供时间、归属、状态与重复触发先例。复用其测试工具和断言习惯，但不能将通用测试结果当作交易授权已实现的证明。
9. **适配器与数据库。** 对模拟与真实适配器运行相同的契约验证。额度占用、幂等、认领与撤销竞态使用实际数据库事务测试，不能只靠内存模拟证明并发正确性。
10. **端到端验收。** 在三类业务上分别完成读数、决策、风控、逐笔批准/范围授权、模拟执行、复盘及候选学习。Web、桌面与适用移动交互检查可见状态、权限与可访问性；原生采集能力单独验证。
11. **语义评价。** 经验意义、解释是否有依据和策略比较结论使用明确、版本化且经过样例校准的评价标准；不以关键词、正则或文本完全一致判定自然语言正确性。结构化字段、权限、数值和可观察交易效果使用确定性断言。
12. **验收追溯。** 测试覆盖既有计划的 V01–V14（当前阶段按上述范围调整记录）：三类闭环、来源数值、版本重放、逐笔批准、范围授权、撤销与不确定状态、审批分权、学习触发、四类入口、版本演进、隔离共享、评价可靠性、模拟与真实隔离、角色场景及跨端。每项记录通过、失败或未执行及原因，不能把部分验证报告为全部完成。
13. **模板与导航。** 通过真实创建界面分别创建四种模板；验证角色持久化、阶段限制、自动绑定和学习计划、失败事务回滚、只读模板不能越权、多个角色连接同一范围、当前 Bot 学习记录筛选、断开连接、人工审批与 Bot 权限分离。检查中英切换、刷新、聊天往返、窄屏操作与旧入口跳转；原生设备验证单独记录。

14. **业务范围与接口。** 验证 Space 一对一业务配置、四模板和普通 Bot 的唯一归属、适用阶段复用、并发创建／重试、失败回滚、真实 Space 切换、全部 Bots 和刷新恢复。验证跨 Space 的 Bot 绑定拒绝及历史迁移不改 ID／证据；多业务旧容器必须安全中止。验证多个数据 API、编辑密钥留空保留、密钥不回显、修订冲突、跨范围／跨身份拒绝、MCP 可见性与工具授权不自动扩大。浏览器覆盖中英文配置、两种业务页内容不同、窄屏和无接口状态；连通验证单独验收，不用“保存成功”代替。

15. **业务归属标签。** 浏览器检查唯一业务归属、跨业务切换、全部 Bots、刷新恢复、中英切换和窄屏展示。新标签不应替换会话预览或状态提示；移动资料页通过既有交互回归及类型检查，原生设备视觉验收单独记录。

## Out of Scope

- 第一版交付时已经接通真实公司系统或真实交易通道；接入点、契约和模拟验收属于本次范围，真实接口取得后另行联调。
- 一次性实现论文清单中全部算法，或把尚未复现的论文结果当成现成功能。
- 对真实盈利、优于人工、全部市场适用性作无证据保证。
- 全国或各省完整现行规则库、所有主体参与资格的预先认定。
- 真实 SCUC/SCED、省间撮合或全部辅助服务品种。
- 重做壳的通用编排、会话、技能和定时任务系统。
- 把业务原始资料默认公开，或把未授权的全程操作监控作为学习前提。

三类主体的完整模拟业务、自动学习、版本验证、人工启用和两种交易批准方式均在第一版范围内。

## 天气预测接入增补（2026-11-04）

使用者要求同时支持天气系统主动推送和本系统主动拉取，并先模拟公司内部天气预测大模型。

- 业务范围内新增天气预测用途；HTTP 接口可主动拉取，HTTP 或推送类型可接收独立令牌认证的预测。MCP 仍沿用原有连接和工具授权。
- 以共享契约保存地点、模型版本、来源类型、签发时间、有效期、预测时段、单位和接收时间。原始批次不可改写；同批同内容幂等，内容冲突拒绝。按签发时间查最新，保留过期与历史记录。
- 所有者管理配置、拉取和令牌；读取服从业务所有者／指定审批人权限。Bot 仅查询已绑定业务范围的预测。外部凭据不得自报另一个业务范围。
- 提供回环地址上的天气服务模拟器，生成明确标记 synthetic 的逐小时气温、风速、湿度、降水、辐照度和云量；不声称运行真实天气大模型或已验证预测效果。

## 模拟业务周期增补（2026-11-05）

本轮按课程架构审查后的明确实施要求，先补一个业务范围内的模拟闭环，暂插在固定版本经验交接之前。保留每业务唯一主管及四类专业 Bot；直接专业会话仍可用。进入交易业务的默认会话选择主管，新增各 Bot 共用的“业务周期”入口。

- 同一周期的合同组合（量、价、参考点、金融／物理属性）、预测、资产可用量与其他物理承诺，由共享服务提供。金融合同参与结算及敞口，不扣成物理占用；物理合同与其他承诺合计不得超过可用电量。
- P25 是显式标注的教学模拟配置，不是上海、江苏或山东现行规则。配置包含主体类型、阶段申报方式、开放／关闸时间、修改／撤销条件及所需前序证据。默认中长期／日前可报量报价，日内／实时仅收结果，已提交报价封存。原意图准备、执行及撤单服务也检查该配置，独立旧分析不能绕过已配置周期。
- 合同、预测、资产、申报回执、出清、履约、计量、模拟账单、内部结算、复盘结果分别保存来源、记录号、状态、内容校验及版本引用。相同来源记录重复导入幂等；内容不同则拒绝。更正追加最新版本，禁止更新旧证据；依赖旧计量的试算和复盘失效并要求重核。
- 教学双偏差：`100×300 + (90−100)×320 + (80−90)×310 = 23700 CNY`；等价差价式相同。该金额仅为电能量结算，不是净利润。无成本／费用时明确待补充，不生成净利润。暂估计量允许暂估试算，不能完成正式的周期核对。
- 主管及专业 Bot 用 `business_cycle` 工具读取同一份证据。主管按需分派合同覆盖、现货分析、风险检查或结算复盘；现货可请求合同／风险帮助，复盘可请求相关专业解释。复用 Ticket、Task/Run 和现有唤醒队列，不新增独立调度器。仅所需角色被唤醒，独立任务可并行；前序资料／任务缺失则阻塞，资料到齐后进入原队列。
- 任务结果包含证据版本、摘要、分歧、未解决事项和可选改进提案。主管不得替专业 Bot 完成有据结果或代替人工批准。普通看板／工具不能将缺证据周期任务标成完成；运行结束不会自动代表业务完成。改进提案只留作待核验建议，不启用算法。
- 中长期／现货 Bot 的周期候选只使用该场景已批准、参数及代码产物匹配的算法；人工可先试算并审核待启用算法。执行时算法启用批准与逐笔批准／范围授权继续分别检查。主管无交易角色；风控与复盘不能分析生成交易候选、准备或执行交易。普通提效 Bot 无本批业务证据访问权限，既有精确资料授权不扩大到整个周期。
- Web/Electron 共用可操作闭环和中英文界面。移动端提供周期、规则、合同及阶段结果、结算、任务与历史的只读查看，聊天共用后端工具；模拟数据导入与人工交易操作明确转到 Web，原移动交易权限不扩大。

交付范围为发电／售电身份下的教学电能量案例。储能身份可查看资料；本例缺少 SOC、效率及多时段轨迹证据，后端拒绝其周期交易分析，不能借固定案例伪造储能可行性。储能原有独立基线不变。完整资产物理模型、跨业务共享资产承诺汇总、真实接口／正式账单接入、三省规则、辅助服务、独立训练及算法插件市场仍待后续。

实现、演示和验证边界见 [模拟业务周期说明](../implementation/eTraderBot-business-cycle.md)。真实模型的拆解、协作及总结质量需单独评估，不以本轮确定性测试替代。
