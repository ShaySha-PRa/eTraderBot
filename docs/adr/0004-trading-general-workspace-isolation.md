# 交易工作区与通用工作区分离

2026-11-04 使用者确认先采用独立工作区方案，复用 Rakazo 的 Space 承载并列的交易工作区与通用工作区。一个交易工作区对应一个业务范围，容纳中长期、现货、风控、复盘四类交易 Bot；普通 Bot 在通用工作区处理提效及其他非交易任务。相比同一业务工作区内共存再逐项限制写入，此方案使交易资料与通用任务的归属更清楚，代价是跨工作区协作需要明确的资料授权。

普通 Bot 默认不能访问交易工作区资源，只有获得明确授权后才能读取指定交易资料；读取授权不允许修改交易文档、记忆、Skill、配置、算法、规则、批准或执行记录，也不授予交易执行权。文件工具、共享记忆、API、MCP 等访问入口都须遵守这一限制，不能借可写共享资源间接修改交易行为；普通 Bot 产生的资料或建议保留在通用工作区，进入交易业务时另行接纳。

**状态：V1.1 首批隔离及最小只读资料授权已实施。** 首批实现工作区类型、创建／复制／导入归属校验、运行时资源与凭据隔离，以及同一使用者名下按指定普通 Bot、单条分析／天气／记忆／Skill 记录授予只读权限。读取当前内容并返回修订标识，授权、读取、拒绝与撤销保留审计；撤销阻止后续读取，已经交付的文字无法收回。范围和限制见 [V1.1 实施说明](../implementation/eTraderBot-v1.1-workspace-isolation.md)，验证证据见 [增量验收记录](../implementation/eTraderBot-v1-acceptance.md)。

决议形成时，V1 允许普通 Bot 与交易 Bot 共处一个业务范围；该行为已由本批隔离约束替代。本次已确认的历史 Bot 归属迁移已完成，归属不明确的历史资源仍须预检及明确计划，不能自动搬运。文件类授权、跨使用者交付及 [ADR 0005](0005-versioned-experience-handoff.md) 的固定版本经验交接不在首批交付范围内。
