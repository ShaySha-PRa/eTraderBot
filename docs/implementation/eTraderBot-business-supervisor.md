# 每条业务线的主管 Bot

2026-11-04。按使用者新增要求，在 V1.1 工作区隔离之后加入业务主管，经验交接继续留待下一批。

## 行为

一个交易业务工作区固定一位主管，四类专业模板保持不变。主管是单独的协调身份，拥有本业务的聊天和记忆；普通通用 Bot 不搬回交易区。新业务配置在同一事务内建立主管，旧业务由所有者首次读取业务配置时补建；待迁移或删除中的工作区不会自动补建。并发创建受工作区锁和唯一约束保护。

主管通过现有任务看板派单，指定同一业务、同一所有者名下的专业 Bot。分配会建立真实 Task/Run 并进入现有工作队列。执行 Bot 用任务状态与评论记录工作，主管可读取全业务任务统计、阻塞项、最新结果、团队活动和历史失败运行，再在对话中汇总。没有新建第二套调度器或独立 Agent 框架。

- 完成率为 `done / 全部任务数`；零任务时为 0。`closed` 在现有看板表示“不做”，单独统计，不算完成。待复核与阻塞也不算完成。
- 统计基于数据库全量聚合，不仅统计最近显示的 30 条任务。任务状态由负责人或使用者维护；它不是独立验证的成果质量或交易收益。
- 一次模型运行结束不会自动完成任务。模型失败保留运行记录；任务应经核实后继续、重新分派或标记阻塞。
- 任务结果保存在评论中，主管读取后按需生成汇总；当前没有额外的定时汇报或主动推送总结任务。
- 主管不能复制、归档、变成交易角色或迁移到另一业务。删除整个业务仍沿用现有工作区删除流程。

## 边界与多端

主管没有交易角色或场景绑定，不能调用交易操作、启用算法、批准意图或获得执行权限。派单不携带或继承主管／其他 Bot 的交易授权，专业 Bot 仍经过原角色、业务、版本、人工批准及额度门禁。主管仅协调所属业务，不管理其他交易工作区或通用区。

`business_overview` 仅向主管提供，后端重查持久化身份和成员关系。人类业务所有者使用同一总览查询；普通 Bot、专业 Bot 和跨区身份不能冒充主管读取该入口。现有任务工具和 RPC 继续按 Space 隔离。交易区的任务看板直接可用，通用区仍沿用原部署开关。

Web/Electron 在主管会话提供“聊天／业务总览”，总览包括任务统计、团队结果和可分派的任务看板，支持中英文及窄屏。移动端从主管资料进入总览、状态和现有原生看板；聊天共用主管工具。尚未运行 Electron 或原生设备验收。

## 2026-11-05 增补：按证据依赖协作

主管作为交易业务默认会话入口，专业 Bot 仍可直接打开。涉及业务周期时，通过 `business_cycle` 按需派单，任务关联固定业务周期、专业角色和前序任务；只唤醒所需角色，已具备资料的独立任务可并行。缺少前序结果、出清、履约、计量或结算则阻塞，资料到齐后沿用 Task/Run 唤醒。一般任务仍可使用原看板。

主管可读取统一证据与各专业结果中的版本引用、分歧、未解决事项和改进建议；不能代替专业 Bot 完成有据结果，不能批准或执行交易。复盘完成需计量、履约和结算证据齐全；更正后旧结算及依赖复盘需要重新核对。计算正确和任务完成均不等于真实模型协作质量已经验收。详见[业务周期实施记录](eTraderBot-business-cycle.md)。
