# 05：撤销工作区访问后的页面处理（前端）

2026-11-07；工作树 `platform-foundation`，分支 `feat/platform-foundation`。依据 05 交接（本地证据 `.scratch/etraderbot-foundation/coordination/05-live-authorization.md`，不在仓库中） 与 [后端记录](eTraderBot-foundation-05-live-authorization.md)。只改 Web 前端、翻译和测试；不改契约、服务端、数据库、04 或 CLI 登记的文件。未提交、推送。

## 原问题

成员资格被撤销后，任何带该业务的请求得到 401 / `UNAUTHORIZED`，`leaveUnavailableSpace` 随即清除业务选择并整页刷新。业务结果草稿只在内存中，刷新后全部丢失；刷新后也没有任何说明；结果表单里的 401 显示的是服务端原文。

## 行为

- 结果表单收到 401 时，在该任务表单内显示“你已无权访问此业务”（随界面语言切换），草稿不动。
- 未发送的结果草稿及其起始版本（结果版本、证据 ID）按业务保存在本设备，自动离开后的整页刷新不再丢失。草稿只在原业务中出现；其他业务读取不到。恢复访问后打开原业务，草稿回到表单，必须由用户自己点击才发送；发送时仍带原起始版本，结果已变化会按原规则得到版本冲突。发送成功后清除。
- 自动离开并刷新后，页面提示一次“你已无权访问之前的业务”。
- 退出登录时清除所有业务结果草稿，与现有聊天草稿规则一致；草稿缺少起始版本或无法解析时丢弃，不半恢复。
- 新增文案 2 条（zh-CN/zh-TW 已翻译）。

修改：`pages/BusinessCycle.tsx`；新增 `lib/business-result-draft.ts`；`lib/rpc.ts` 在离开前写一次性标记并提供读取；`App.tsx` 显示离开提示；`lib/sign-out.ts` 清除结果草稿。E2E 的业务/周期准备函数从 `business-cycle-drafts.spec.ts` 移入 `e2e/trading-business-helpers.ts` 供两份测试共用，行为不变。

## 限制

- 浏览器路径在中文 390 下完成；英文提示由单元测试覆盖。
- 暂缓 `spaces/list` 只为让提示在刷新前可被截图；实际用户场景中刷新可能很快发生，此时依赖刷新后的离开提示和已保存草稿。
- 草稿保存在浏览器本地存储，直到发送、清空或退出登录；同一浏览器的其他账号读不到（退出登录即清除），但未退出时它留在本设备上。
- 未运行 Electron、原生移动端和真实模型。移动端没有业务周期结果表单，不涉及。

## Desktop 独立验收

使用独立测试库，不使用其他票的验收库。

1. 在业务 A 的业务周期填写一个任务的结果草稿（不提交）。
2. 在测试库撤销该用户对 A 的成员资格，再在旧页面点击“记录有据结果”：网络应为 401 / UNAUTHORIZED；页面离开 A 并提示“你已无权访问之前的业务”（如来得及，表单内先显示“你已无权访问此业务”）；数据库没有新证据、评论或工单变化。
3. 切换到仍有权的业务 B：不出现 A 的草稿、工单或证据；B 的提交只带 B 的工单。
4. 恢复 A 的访问并打开 A：草稿回到表单，不自动提交；点击后才记录一次。
5. 中英文、390 CSS px 下复核；退出登录后再登录，草稿应已清除。
