## 2. 目标与非目标

### 2.1 目标（做小、做实）

1. 在 rakazo 上挂好四个交易相关 Bot，通过 **统一交易数据 Port** 读内部（或桩）数据。\
2. **算法版本库**：交易员/Bot 沉淀的决策算法可存、列版本、调用；新版本须经复盘门槛 + 人审。\
3. **门禁**：影子默许跟学；实盘申报、改限额等写操作必须过人审门禁；风控 Bot 解释与升级，**放行权在门禁服务**，不在聊天。\
4. 先契约与桩跑通「读数 → 调用某算法版本 → 产出候选（带来源）→ 影子记录 →（可选）人审」，再逐个换真接口。

### 2.2 非目标 / 红线

| # | 不做 |
|---|---|
| N1 | 用第二套重型编排框架（另起 LangGraph 大图等）**替代** rakazo 的会话/派活/routine |
| N2 | 大改 rakazo UI / 重做花名册与 PI 模型 |
| N3 | 真 SCUC/SCED、省间撮合、辅助服务实盘 |
| N4 | 编造或固化「全国现行」时刻表/限价/考核参数表 |
| N5 | LLM 生成价格、持仓、SOC、最终报价或补造审批理由 |
| N6 | 影子未过审就实盘，或技能/算法自动改 live 限额 |
| N7 | 把现货拆成日前/日内/实时三个花名册 Bot（用 skill/routine 覆盖即可） |
| N8 | 复盘未过就发布算法新版本到可调用池 |

## 3. 架构落点（最小）

```text
交易员 ↔ rakazo（花名册 / 会话 / routine / skill / 互派）
              │ 只增加「交易工具」接线
              ▼
     门禁 Gate（影子 | 人审 | 实盘/改限额）
              │
              ▼
     交易数据 Port（契约；先桩后真接口）  +  算法版本库 AlgoRegistry
              │                                    │
              └────────► 候选/记录（带来源：接口ID或算法版本）◄──┘
```

- **rakazo 保留**：PI、花名册、会话、委派、routine/skill。\
- **新增（后端小服务或同仓模块即可，形态待补充）**：交易数据 Port、AlgoRegistry、Gate、审计日志。\
- **不**要求先建完整电力市场状态机产品；若日后要申报回执分层，再单列里程碑（当前不展开臆测模块清单）。

## 4. 模块清单（仅必要）

| 模块 | 做什么 | 不做 |
|---|---|---|
| **MarketDataPort** | 按契约拉行情/负荷/机组或储能状态/合同摘要等（字段**待补充**，以公司接口为准） | 不在 Port 内「猜」数；无接口则 `StubNotConfigured` |
| **PositionExposurePort** | 读中长期敞口、已承诺等只读视图（契约待补充） | 不让 Bot 口头改敞口 |
| **AlgoRegistry** | 存算法：id、版本、作者、适用范围、输入输出 schema、产物哈希、状态（draft/candidate/live/retired） | 模型对话不能直接改 live |
| **AlgoRunner** | 按版本调用算法，返回结构化结果 + `algo_version` + 输入快照 id | LLM 不得顶替 Runner 填数 |
| **Gate** | `shadow` 默认；`request_live` / `change_limit` 必须人审令牌；校验令牌绑定意图哈希与有效期 | 风控 Bot 文本「通过」无效力 |
| **RiskBot 工具** | 调确定性检查（限额、简单占用冲突——规则来源待补充）并解释拒绝码 | 不是审批人 |
| **ReviewGate（复盘门槛）** | 复盘任务完成并记录后，才允许 AlgoRegistry 开新版本或 draft→candidate | 复盘 Bot 不能私自 merge live |
| **AuditLog** | 谁、何时、读了哪接口、调了哪算法版本、是否影子、人审结果 | 不删历史 |

**现货 Bot**：一个花名册角色；日前 / 日内 / 实时用 **不同 skill 或 routine** 切换检查清单与工具子集，不新开三个 Bot。

## 5. Bot × 能力（简表）

| 能力 | 中长期 | 现货 | 风控 | 复盘 |
|---|---|---|---|---|
| 读 MarketData / 敞口 | ✓ | ✓ | ✓ | ✓ |
| 写合同/敞口主数据 | 仅经门禁+专用工具（细节待补充） | ✗ | ✗ | ✗ |
| 调 AlgoRunner | ✓（中长期类算法） | ✓（现货类） | 只读结果做检查 | 只读 |
| 提算法 draft | ✓ | ✓ | ✗ | 可提案，须过复盘门槛 |
| merge→live / 改限额 | ✗（须人审 Gate） | ✗ | 可反对/升级，**不能自批** | 复盘门槛签字 ≠ 人审实盘 |
| 触发实盘类写操作 | 人审后 | 人审后 | ✗ | ✗ |
| 复盘报告 / 开版本门槛 | 配合补证 | 配合补证 | 异常调查 | **主责** |

## 6. 里程碑（依赖顺序）

### P0 — 契约 + 桩（无真公司网亦可）

1. 写下 `MarketDataPort` / `PositionExposurePort` / `AlgoRunner` 的 Pydantic（或等价）输入输出；空字段标待补充。\
2. 实现桩：固定合成 JSON，所有数带 `source=stub|synthetic`。\
3. `AlgoRegistry` 最小表：注册两个示例算法版本（如「中长期敞口摘要 v0」「现货候选透传人工表 v0」——透传也算算法，禁止 LLM 改数）。\
4. `Gate`：shadow 全开；live/改限额无令牌即拒。\
5. 验收：现货 Bot skill 调桩数据 → Runner → 返回带来源的候选；无令牌实盘失败。

### P1 — rakazo 接线（最小）

1. 四 Bot 人设 + 工具白名单指向上述 API。\
2. 现货：挂「日前 / 日内 / 实时」三条 skill 或 routine（内容=检查清单+调哪些 Port），**仍一个 Bot**。\
3. 审批卡字段对齐 Gate 令牌（身份、意图哈希、有效期）。\
4. 验收：交易员在影子下带教；人审通过后同意图可打 live 标记（真报盘适配器仍可后接，标待补充）。

### P2 — 跟人学与进化闭环

1. 跟学记录：交易员操作/口头规则 → 沉淀为 skill 或算法 draft（人工整理入口待补充）。\
2. **复盘后**才能 `draft → candidate`；再人审才能 `candidate → live`。\
3. 风控 Bot 接入限额/冲突检查（阈值来源待补充；未核实则只告警不放行）。\
4. 验收：无复盘记录则拒绝开新版本；live 算法调用可追溯版本号。

### 后置（本计划不排期）

真公司接口清单与鉴权、真报盘通道、SCUC、辅助实盘、全国/省现行参数库、大改壳。

## 8. 壳侧（rakazo）

### 做

- 配置四角色；加交易相关 tools → 后端 Port/Gate/Algo。\
- 审批/影子开关与 Gate 对齐。\
- routine/skill 承载日前·日内·实时与跟学清单。

### 不做

- 不重做编排内核、不大改 UI、不把电脑/宽权限映射成交易权。\
- **本轮不改仓库代码**；实现另立项。

---

## 9. 自学习（收敛写法）

1. **跟学**：影子模式下记录交易员决策与反馈 → 人工或半自动写成 skill / 算法 draft。\
2. **存**：AlgoRegistry + skill 版本。\
3. **进化**：复盘门槛 → 人审 → live。\
4. **调用**：Bot 只通过 AlgoRunner 调 live/允许的 candidate（策略待补充）。\
5. **禁**：对话回合直接改 live 限额或规则。
