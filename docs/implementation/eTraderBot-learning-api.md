# eTraderBot 学习流程：当前实现与边界

本批在 `feat/etraderbot-v1` 实现 M4 的参数候选流程。它复用现有 Routine、Task、Run、模型连接、后台恢复和费用记录，不要求新增模型密钥或供应商。完整 v1 尚未验收。

## 使用流程

1. 在交易页面绑定 Bot，会建立每日学习计划。初始为 `02:00 / Asia/Shanghai`，这是可编辑默认值，不是固定业务要求。已有旧绑定可重新点击绑定补建计划。修改时间、时区、基线参数或暂停状态后，页面显示实际安排及下次执行时间；解除绑定会暂停计划。
2. 使用者可保存交易员反馈、上传 UTF-8 文本、Markdown、CSV 或 JSON 文件，或明确附加该 Bot 会话中的用户消息。上传大小上限为 64 KB。不会自动把共享 Bot 的所有聊天归入一个业务范围。
3. 每日定时与“立即学习”进入同一个流程，模型使用 Bot 现有连接。系统收集当前账户、精确业务范围匹配的历史分析及已授权模拟操作。输入、基线参数、引擎与验证配置固定并计算摘要。
4. 模型只能查看该次训练资料并提出一个非负加价／价差门槛参数、假设、经验及来源引用。学习运行不加载普通会话历史、共享记忆或其他工具，也不能准备或执行交易。
5. 服务按原始观察时间重算基线和候选，保存对照报告。候选只有通过数值约束且有足够独立历史窗口，才关联一个待人工启用的版本。原本已有相同版本时复用其身份，不重复生成。任何新版本都不会继承交易授权。

资料和派生经验默认保留在原业务范围。显式共享需要已确认身份的范围创建者操作，目前支持在同一使用者拥有的范围之间共享选中的经验文字；不会开放原始资料或原报告。跨使用者的共享流程尚未实现。

## 内部接口

| RPC | 用途 |
| --- | --- |
| `trading.learningState` | 计划、资料、运行状态、错误和报告 |
| `trading.configureLearning` | 设置每日时间、时区、启停和基线参数 |
| `trading.addLearningSource` | 保存反馈或使用者提供的文本文件内容，按内容摘要保留修订 |
| `trading.captureLearningMessage` | 按真实消息 ID 附加该 Bot 会话中的用户文字 |
| `trading.startLearning` | 手动启动；保留请求键并复用相同输入/验证配置的在途任务 |
| `trading.shareLearningExperience` | 经身份确认，将指定经验文字复制至另一个自己拥有的范围 |

Bot 的 `trading` 工具增加 `learning_schedule`、`learning_capture_message`、`learning_start`、`learning_open`、`learning_propose`。身份和 Run 来自服务端，模型不能自报执行者。学习任务只开放 `scopes`、`learning_open`、`learning_propose`，且只能访问自己的学习范围。

Web 和桌面提供计划、资料、手动启动、报告和共享入口。移动端可查看安排、报告、错误并手动启动；资料管理和完整证据查看在 Web，对话可修改安排。原生设备验收尚未执行。

## 验证证据

验证版本为 `constraints-temporal-hidden-holdout-v2`，固定输入摘要包含来源摘要、基线参数、当前引擎及该验证版本。服务按交割窗口排序并排除重叠窗口，训练窗口必须早于留出样本的观察时间。至少需要两个训练窗口和一个留出窗口。留出快照内容不进入模型输入，候选提交后才计算其结果；同一会话只能提交一份不可改写的报告。

报告记录基线与候选的订单名义金额、未覆盖敞口、硬约束结果、错误、来源、引擎摘要和验证版本。`constraints_passed` 只表示这些数值约束通过；`insufficient_data`、`constraints_failed`、`no_data`、`no_new_data` 均单独保留。语义评价固定为 `not_evaluated`，收益结论固定为 `not_established`。

学习资料最多选取最近 100 份、合计不超过 160,000 字符；历史分析最多取最近 30 份，模拟操作最多 20 份。上限内实际选入的资料会固定保存。当前历史入口仍是内置合成分析，不能据此证明实盘收益、交易员水平或论文效果。

每日任务沿用现有停机补偿：合并遗漏窗口补一次。每日/手动触发在对应业务范围锁下比较输入及验证配置，相同在途任务复用，新资料可形成后续任务；不存在全局串行槽。手动请求别名持久化，完成后重试原请求键仍指向原任务。失败任务保留原因，新请求可重试，费用继续由既有 Run 使用量记录承载。

## 尚未交付的部分

- 当前只支持既有固定算法的参数候选；自由代码、模型训练产物及其他算法版本的受限执行尚未接入。
- 没有接入原生 PDF/Excel 解析、真实公司历史数据或自动采集所有聊天；需要明确附加或提供支持的文本资料。
- 2026-11-04 使用者明确搁置论文算法实现；独立收益评价、经校准的自然语言验证及真实模型学习效果／费用仍未验收。
- 来源引用只能证明提交者引用了授权资料，不能证明经验文字可靠；自然语言质量不得用关键词匹配充当通过证据。
- 三类主体的完整学习改进验收、跨使用者共享及原生设备检查仍在 M4/M5 剩余范围内。

## 本批检查

PostgreSQL 测试通过实际注册的 Bot 工具处理入口覆盖三类参数候选、训练/留出隔离、两类审批独立、失败/空资料、资料固定、四种来源、共享边界、在途复用、每日/手动并发、遗漏窗口补偿和证据不可改写。浏览器验证了计划修改、反馈保存、文件上传、手动启动、刷新恢复、中英文与窄屏。离线模型未生成真实学习结论；实际模型调用效果未验收。


## 执行回执反馈修订（2026-11-04）

操作资料保存订单最新持久化回执和完整有序历史，核对或撤单新增的证据形成新资料版本，已经固定的学习输入不覆盖。三类主体的候选版本在人工启用后仍须独立交易批准，部分成交核对后的结果可进入下一次学习。每日或手动创建的学习运行只允许读取学习范围、提交学习报告，不允许执行、核对或撤单。

这些检查证明资料、状态和权限闭环，报告仍为 `semanticEvaluation=not_evaluated`、`performanceConclusion=not_established`。论文与真实数据效果恢复前不宣称策略已改进。
