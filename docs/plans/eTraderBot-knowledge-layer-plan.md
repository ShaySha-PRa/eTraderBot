# eTraderBot 知识层计划（规则条文 · 说明文档 · RAG / Ontology）

状态：**未定选型，已入计划**。2026-11-03 讨论确认：业务事实走版本化账本；说明类材料可以另建知识层；RAG 与 Ontology 用途不同，待选型后实施。不编造公司接口、现行省参与收益数字。

关联：[eTraderBot-v1-implementation-plan.md](./eTraderBot-v1-implementation-plan.md)、[09-eTraderBot-source-plan.md](./09-eTraderBot-source-plan.md)、储能本体 demo（`handoff-saoa` / 面试包 `04`）。

---

## 1. 问题

现货等 Bot 长期运行时：

- 聊天上下文不能无限累加喂模型（展示可全量，推理用窗口 + 摘要 + 按需拉数）。
- 业务事实（合同、占用、审批、出清等）必须是**版本化账本**，不是知识库。
- 规则条文、SOP、手册等说明材料需要检索辅助，但**不能**当作放行或改数的权威。

因此需要单独规划「知识层」，与账本、壳记忆、算法版本分开。

---

## 2. 三层边界（已确认口径）

| 层 | 存什么 | 权威吗 | 形态意向 |
|---|---|---|---|
| 对话／角色记忆 | 消息、摘要、偏好、简介 | 否（仅协作上下文） | 壳侧；窗口 + 摘要 |
| 业务事实账本 | 合同、敞口、意图版本、审批、回执、出清／计量凭证 | **是** | Postgres 版本化表／事务；非 RAG |
| 知识层（本计划） | 规则原文、SOP、操作手册、字段说明、架构笔记等 | 否（辅助检索／解释） | **待定**：RAG 和／或 Ontology |

规则**执行**另有 `RuleRegistry`（文号、生效窗、适用省／产品／阶段、规则快照）。知识层可指向原文；放行与约束检查只认 Registry 快照与账本，不认检索片段。

---

## 3. RAG 与 Ontology：各自合适场景

| 方案 | 更合适 | 不合适 |
|---|---|---|
| **RAG** | 规则 PDF／公告、SOP、手册、培训笔记等非结构化说明的检索与引用 | 当价格、持仓、SOC、审批结果；替代 `RuleRegistry` |
| **Ontology** | 资产／场站／设备关系、字段约束、与储能本体 demo 一类结构化世界模型 | 替代交易账本或申报状态机 |

结论倾向（待拍板）：

1. 说明文档检索 → 优先考虑 **RAG**（可后接 MCP 外挂公司文库）。
2. 资产与经营对象结构 → 可复用／延伸 **Ontology**（对齐已有储能本体 demo），不替代交易账本。
3. 两者可并存；都不是业务事实权威。

**尚未决定**：第一版是否做知识层、先做 RAG 还是 Ontology、内置索引还是 MCP 外挂。

## 4. 接入形态（倾向，未锁定）

| 用途 | 倾向 | 理由 |
|---|---|---|
| `RuleRegistry` + 限额／适用条件 | **内置**后端服务 | 版本、生效窗、审计、与门禁同一信任边界 |
| 说明文档检索 | Demo 可先**内置**本地索引；公司文库成熟后再 **MCP 外挂** | MCP 便于换源；不能授予写权限或绕开门禁 |
| Ontology | 与资产域模型同仓或独立服务；Bot 只读查询工具 | 结构化约束可校验；仍不产出申报数字 |

硬约束：

- LLM 不编数；检索结果只作引用，数字仍来自 Port／算法版本／人工候选。
- 对话回合禁止直接改 live 限额或规则。
- 跟学沉淀走 skill／算法 draft → 复盘过线 → 人审后升版；不进「检索即生效」。

## 5. 建议纳入主计划的工作包（未排期）

| ID | 工作包 | 产出 | 依赖／备注 |
|---|---|---|---|
| K0 | 选型决议 | 一页 ADR：RAG／Ontology／并行；内置 vs MCP | 产品拍板 |
| K1 | 语料边界清单 | 可进知识层的文档类型 vs 必须进账本／Registry 的类型 | 与法务／交易规则来源待补充项对齐 |
| K2 | `RuleRegistry` 最小契约 | 文号、日期窗、适用条件、快照哈希、未核实状态 | 第一版可空配置，但接口先定 |
| K3 | 说明文档检索 MVP（若选 RAG） | 本地语料 → 检索工具 → 带来源片段；无放行效力 | 可后换 MCP |
| K4 | Ontology 只读查询（若选／并行） | 资产关系查询工具；与储能本体 demo 映射说明 | 不写入交易账本 |
| K5 | Bot 工具权限 | 现货／中长期／复盘／风控各自可见的检索工具白名单 | 风控与门禁不读「检索通过」当审批 |

验收原则：有来源引用；未核实规则不得激活为执行依据；知识层故障时交易主路径仍可用账本 + 桩／Port。

## 6. 明确不做（本计划范围外）

- 用知识库替代 Postgres 业务账本。
- 用 RAG 片段自动改报价、限额或审批状态。
- 宣称已核实现行省规则或已接入公司文库（当前均为待补充）。
