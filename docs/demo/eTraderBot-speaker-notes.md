# eTraderBot 演示讲稿

按当前七页演示顺序整理，供讲述者单独阅读。能力口径已按 V1.1 首批交付更新；讲述内容、现场演示提示与参考资料均保留在本文件中。

## 第 1 页｜自动化 AI 交易员平台

今天介绍 eTraderBot，一个自动化 AI 交易员平台。平台希望让 AI 交易员通过向有经验的交易员学习，逐步掌握专业判断与工作方法，并在明确授权范围内自主开展交易工作。

在强大模型驱动下，各 Bot 分工完成分析、决策、执行与复盘。右侧两条路径同步展开：AI 从跟学积累走向验证能力，再到授权下自主工作；人类交易员从带教与纠偏，逐渐转向评估、审核、批准和监督。

业务学习通过记忆、经验总结与 Skill 帮助 Bot 理解和处理工作；交易量价候选由独立版本算法计算。影响交易决策的变化须进入受控算法或规则版本，安装算法、调用工具与获得交易授权分别管理。

能力进展仍由验证证据与人工批准决定，学习完成不自动授予交易权限。规则、物理约束与执行门禁贯穿各阶段；这两条路径表示角色和能力的演进，不表示所有工作都必须依次等待，或执行后才进行批准。

封面表达平台定位与演进目标。V1.1 首批已实现交易／通用工作区隔离、按 Bot 和记录授予只读权限、撤销与审计；天气接口已支持 HTTP 拉取和外部推送。当前演示仍使用合成数据与模拟执行，尚未接入真实公司数据或交易通道。后续结合应用现场演示这些已交付能力。

## 第 2 页｜让交易员的经验，成为可持续积累的 AI 交易能力

这一页先讲客户能获得的三个核心价值。可带教：把交易员的判断理由、纠偏和复盘沉淀下来，形成有来源、适用条件和局限的记忆、经验与 Skill。

可自主：Bot 在明确授权范围内完成工作，人的角色逐渐转向审核、批准和监督；具体交易仍由后端校验业务范围、算法版本、时效与额度。可传承：选定且获授权的经验以固定版本交给新 Bot，在新业务中验证、纠错和独立积累，凭据与交易权限不随经验继承。

底部三项是这些价值的共同支撑：独立算法计算量价，执行门禁控制交易边界，关联证据支持审核与复盘。业务过程可追溯不代表大模型内部推理完全透明。

本页表达产品目标，不表示完整能力已经交付，也不主张竞品不具备这些能力。V1.1 已补齐首批工作区隔离与逐条资料只读授权，完整经验交接仍待实施，真实策略效果尚未验证。后面的行业难题、架构、交易、学习和交接页面依次展开。

## 第 3 页｜从交易员经验，到受控的 AI 决策

本页按已确认的三条主线讲述：交易员教会 AI 怎么判断，大模型与 Agent 架构把这些经验用于实际工作，规则和门禁保障执行边界。文章中的问题作为右侧对照，页面的中心是经验如何形成判断、进入工作并受到执行约束。

这里将经验学习具体落实到记忆、经验总结与 Skill；它不等于模型权重自动更新。独立算法训练与业务经验积累分别管理，影响交易量价、约束或风险预算的修改须进入受控版本并验证批准。

第一条主线是学习与蒸馏经验。交易员不仅提供做过什么，还解释在什么场景下、为什么这样判断、何时不应该继续交易。因果判断与停止条件都放在这一条主线下。极端案例、物理机制检验、压力测试和独立留出验证用于检查经验的适用边界；经验与合成样本能够补充验证覆盖，但不能替代真实事件证据，也不能直接证明因果关系。

第二条主线是将经验用于实际工作。大模型结合蒸馏经验识别重要信号，Agent 按业务范围组织资料、协作角色和算法调用。数据来源、规则、算法版本、批准与回执保持关联，Bot 引用这些依据解释操作。这里把模型与经验对信号识别的作用，以及架构对资料组织和证据追溯的作用放在一起；效果仍需验证。

第三条主线是保障执行边界。物理约束和适用规则进入校验，规则版本更新后重新检查受影响策略；执行前核验授权、时效和额度，先通过模拟发现问题，再按明确条件执行、拒绝或交还人工。学习到的停止条件需要经过验证并落实到执行机制。订单提交超时属于结果不确定，不能代替行情置信度判断，也不能据此释放额度或重复提交。

底部的全链路追溯贯穿三条主线：数据来源与快照、经验来源与版本、规则和算法版本、候选决策、批准授权、执行回执，以及复盘学习记录。它让人能够核查一次操作依据了什么、经过谁批准、最终发生了什么，减少无法核查的黑盒操作。这里指业务决策与执行证据可审计，不代表大模型内部推理完全透明，也不保证解释本身正确；记录还需支持交叉核查。

按当前验收记录，内部合成数据下的基础算法、参数候选、批准、额度与回执流程，以及天气接入、工作区隔离、资料授权和撤销审计已通过相应定向验证。完整经验蒸馏、场景标签与类比检索、极端行情压力测试、因果建模、预测置信度机制、权威规则更新与真实模型解释质量仍需补充或验证。本页呈现产品设计与演进方向；真实效果另行验收。原文的训练数据用量与回撤改善数字是作者对其系统的自述，未独立核实，不作为本项目成果。

## 第 4 页｜按业务组织 Bot，按权限开展协作

本页展示 V1.1 首批已实现的工作区隔离与资料只读授权。平台参考 grokbot 的 Bot、会话、记忆、Skill 与任务机制，承载两类并列工作区。交易工作区对应一个具体业务范围，地区用于组织业务；“全部 Bots”汇总导航，打开 Bot 时切换到其实际工作区上下文。

四类交易 Bot 只能归属交易工作区，普通 Bot 只能归属通用工作区。创建、复制和导入均检查归属，运行开始与工具调用时继续核验身份和资源边界。现货的日前、日内、实时是工作场景；风控和复盘提供检查、解释与总结，没有下单或撤单权限。

当前只读授权由源交易区所有者发起，接收方限定为同一使用者名下、通用区内的指定普通 Bot。资料精确到单条分析、天气批次、记忆文档或 Skill。普通 Bot 默认不可见，获授权后读取该记录的当前内容与修订标识，不能借此取得源区写权限、工具或交易权限；建议保留在通用区，进入交易业务时另行接纳。

授权、读取、拒绝和撤销都留有审计。撤销阻止后续读取，已经交付的文字无法收回；复制或导入 Bot 不复制资料授权。这一能力是按记录的只读访问，固定版本经验交接包和独立导入仍留待下一批。

V1.1 首批已实现工作区类型、后端与运行时隔离、最小只读授权，并完成本次已确认的历史 Bot 归属迁移。资料授权管理在 Web 完成；原生设备、Electron E2E、真实模型效果与真实公司接口未在本批验收。隔离覆盖应用管理的资源与凭据，外部 HTTP／MCP 服务的账户权限仍需该服务自身实施。

天气接口已经支持 HTTP 主动拉取、外部令牌推送、来源与批次留存，以及绑定交易 Bot 的查询。当前联调对象是生成合成数据的天气模拟服务，不运行真实气象模型。天气供查询与解释，尚未自动转换为负荷／新能源出力、交易参数或算法学习输入。

**现场演示切换提示：**在此切到应用，按以下顺序展示已交付功能：

1. 切换交易与通用工作区，展示交易区的四类模板和通用区的普通 Bot，以及“全部 Bots”打开后的工作区切换。
2. 在交易区的接口设置中打开“资料只读授权”，为同一使用者名下的指定普通 Bot 选择一条资料并授权。
3. 在已准备好的工具演示环境中，由该普通 Bot 调用资料读取工具，展示读取结果与审计。现场模型对话只演示已确认可用的链路；本批验收不代表真实模型对话已经验证。
4. 撤销授权，再次读取应被拒绝，查看撤销和拒绝读取记录；已经展示过的文字不会自动消失。
5. 可选展示天气接口从本地模拟服务拉取预测，并查看来源、签发时间、有效期与逐小时指标；外部推送使用预先准备的模拟流程。
6. 返回第五页，继续讲模拟交易、批准与执行回执；第七页的固定版本经验交接仍作为后续目标说明。

## 第 5 页｜一笔交易，如何在授权下完成

点击“逐步演示”推进五步，也可以直接选择节点回看证据。“已展示”只表示讲解进度，不代表真实任务执行成功；本页不调用模型或提交任何交易。

上方是独立的算法发布入口：候选版本经验证与人工启用，发布为可调用的固定版本。交易流程中 Bot 固定数据、调用获准算法，算法计算量价并生成结构化候选，后端再核验逐笔批准或范围授权、时效、规则与额度。算法启用不是每笔交易都重新进行的同一项审批；交易授权继续逐次核验。风控 Bot 的意见不替代人工批准或后端门禁。

“查看额度变化”展开沿用的教学订单：10 MWh × 400 元/MWh = 4,000 元毛名义额度。提交时全部占用；确认成交 4 MWh 后，1,600 元核销，2,400 元仍占用；核对超时保持占用；只有确定回执才能核销或释放。最后的确认全成仅是本示例结局，不意味着超时后必然成交。

撤销授权阻止新增提交，撤单用于取消既有订单，两者分别管理。原订单继续跟踪核对；相同请求重试复用结果，不更换请求键盲目重提。当前讲解基于合成数据和模拟执行，真实通道与策略收益另行验证。

## 第 6 页｜经验持续积累，算法经过验证再启用

本页展示两种不同的学习。第一条通过记忆、经验总结和流程 Skill 帮助 Bot 理解业务、组织协作，并在来源与资料权限范围内持续纠错；这不是模型权重自动更新，也不自动证明专业判断有效。

第二条面向交易计算：从交易员反馈、复盘和研究提出算法改进候选，固定输入与版本，经独立训练与验证、约束检查、目标中的影子运行和人工启用，再发布固定版本。新版本必须独立取得交易授权。影响交易量价、约束或风险预算的 Skill 变化同样进入受控算法或规则版本流程。

当前已有底座记忆与 Skill，以及固定算法参数候选、训练与留出验证和人工启用的工程流程。独立强化学习（可探索 agentic RL）、完整算法插件发布和真实策略效果仍是后续目标。验证数值和硬约束，不能推导出实盘收益改进。

## 第 7 页｜让经验在新业务中继续积累

经验交接让旧业务积累的知识能够经授权服务新业务。流程从选择内容和授权开始，只包含选定且获准导出与目标使用的记忆、经验、Skill，不默认迁移全部聊天或原始业务资料。

交接包固定版本并保留来源、适用条件和局限。目标 Bot 接纳独立副本后，在新业务中验证、纠错和继续积累；原包保留不变。源 Bot 后续修改形成新包，由目标明确接纳，不能自动覆盖目标已积累的内容。

交接不继承凭据、角色权限、算法启用批准、交易批准或额度。影响交易计算的内容继续经过受控版本验证与批准。旧业务结束不自动删除已授权导入的经验，原始交易证据仍归属原业务；授权撤销后的保留与使用规则还需细化。

本页的固定版本经验交接仍是已确认、待实施的下一批目标。V1.1 的只读授权绑定单条资料记录，读取其当前内容与修订标识；固定版本交接包、独立副本、导入追溯与更新冲突处理另行实施。现有记忆、Skill、Agent 导入与只读资料授权作为后续建设的基础。
