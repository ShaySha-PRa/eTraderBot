## 第一批已实现

- 三类主体的统一数据、规则、来源、意图、回执与学习资料契约；由同一 Zod 定义生成外部 OpenAPI 3.1。
- 三类确定性计算基线：售电按报价分配净敞口，发电按承诺电量与分段成本生成增量报价，储能按价差、效率、功率、电量上下限及终端储备生成计划。它们是透明的工程基线，尚不是论文复现，也没有真实收益验证。
- 6 位定点十进制计算；来源时序、规则覆盖、价格/电量步长、主体一致性及储能物理约束检查。
- 壳内认证 RPC：`trading.simulate`、`trading.get`、`trading.history`、`trading.replay`。模拟入口使用内置合成快照，保存输入、参数、候选与计算时间；历史重放使用原观察时间并比较结果，不延长资料有效期。
- 增量数据库迁移及用户、Space 双重行级隔离。现有 API 没有修改分析证据的操作。
- 外部样例离线校验命令，可在不修改样例的情况下报告结构及算法输入问题。

第一批算法标识曾只绑定种类、修订号及参数；第二批已改为绑定当前引擎内容摘要和参数，并加入版本归档与启用审批。分析记录本身不构成交易批准。

## 第二批已实现：批准与模拟执行

- 新增明确的模拟业务范围，分别指定算法审批人与交易授权人；两人必须属于当前 Space，可由同一人兼任。Space 权限不会自动取得业务审批资格。
- 新增受身份确认保护的角色配置、算法启用/退役、逐笔批准与范围授权/撤销 RPC。每次操作使用服务端身份，并检查其指定职责。
- 固定意图内容、来源快照、参数、算法/规则版本及有效期，服务端保存摘要。引擎源码表示、schema 与 Node 版本形成固定审核内容；引擎变化不能沿用旧批准。
- 交易执行前重新计算和检查候选，拒绝范围不符、数据/意图/授权过期、交割时段已开始、版本未启用、未批准、单笔或累计超额等情形。
- 内置模拟器按限价全部成交，生成 synthetic 回执；按请求幂等，重复请求返回原执行，同意图换键再提交被拒绝。
- 额度扣减、执行与审计在同一 PostgreSQL 事务中提交，锁仅作用于对应业务范围，撤销和提交也由同一锁协调。授权撤销后仍可查询已提交结果。
- 数据库保护审核依据不可改写、已用额度不可重置，业务资料仅显式指定的参与人可见，并继续隔离不同 Space。
- [内部批准与执行 API](eTraderBot-trading-control-api.md) 记录实际接口、计量口径和当前边界；[外部样例校验报告](../integration/eTraderBot-fixture-validation.md) 列出需数据 agent 修正的文件。

## 第三批：Bot 工具与产品入口

- 交易服务移入共享数据库包，API 和 worker 使用同一套业务校验、版本标识、事务及授权逻辑。
- 注册 `trading` 内置工具，提供范围发现、上下文读取、分析、准备意图和模拟执行。身份来自持久化 Run，工具参数不能自报使用者、Space、Bot 或批准状态。
- 业务范围可明确绑定中长期、现货、风控、复盘角色；现货角色承载日前、日内、实时，中长期角色只在中长期场景写入，风控和复盘角色只读。技能/说明文本不构成权限。
- 新增 Bot 绑定配置和解除配置，要求已确认身份的范围创建者操作。意图和范围授权均绑定执行 Bot，执行时在业务范围锁内重新检查，解除绑定或改为只读角色后不能继续提交。
- Web 新增交易入口及 `/app/trading`，桌面复用该页面。可创建模拟范围、选择两类审批人、运行分析、检查依据、逐笔批准或限额授权、绑定 Bot、查看模拟成交与审计。明确业务拒绝后可以更换授权；通信结果不确定时保留原幂等请求。
- 移动端新增交易入口，可查看范围、候选订单、版本及回执，执行算法/交易批准、退役与授权撤销；创建范围、配置授权和 Bot 绑定暂由 Web 承载，页面有明确说明。
- 新增中英文文案、浏览器验收场景、移动端交互测试及现有 iOS 截图目录中的交易空状态流程。iOS 原生截图尚未在本机执行。
- Web 与移动端交割时间遵循规则中的市场时区，显示时区偏移；时间格式随界面语言切换。
- 本地开发服务已启动在 `http://localhost:5173/app/trading`，已复制原账号和资料到独立分支数据库并应用三项新迁移。原共享数据库已备份，未应用本分支的新迁移。

## 第四批：每日／手动学习与参数候选

- 绑定交易 Bot 时建立可修改的每日 Routine；Web 可设置时间、时区、基线参数、启停并手动触发，Bot 对话工具也可修改安排。移动端可查看并手动启动，资料管理与完整证据由 Web 承载。
- 四类学习资料保留业务范围、引用和摘要：明确附加的用户消息／反馈、上传的文本文件、已授权模拟操作、当前账户同一范围的历史分析。资料修订、固定输入、报告及请求键持久化，来源和报告受数据库不可改写保护。
- 学习运行只接收当前训练资料与学习工具，不接收普通聊天、共享记忆或外部工具；持有交易授权也不能借学习运行准备或执行订单。共享需要经身份确认，且仅复制选定经验文字，不扩大原资料权限。
- 每日与手动触发在对应业务范围锁下复用相同输入、基线、引擎和验证配置的在途任务，覆盖 queued、leased、running 和等待状态；新资料形成后续任务。手动请求别名保留，失败可新请求重试；停机遗漏窗口沿用 Routine 补一次。
- 模型可提出参数、假设、经验及来源引用；服务固定时间分隔的训练/留出样本，留出快照不进入模型输入。至少两个训练窗口、一个留出窗口且约束通过，才能关联候选版本；启用仍需要人，交易批准继续独立，新版本不继承授权。
- 保存版本化的数值对照、来源、引擎和输入摘要。缺数据、无新资料、约束失败与运行失败分别可见。收益结论和语义评价保持未建立／未评价，不把流程成功标成学习效果成功。
- 当前仅支持已有固定算法的加价／价差门槛参数候选。其他算法/模型产物、PDF/Excel 解析、跨使用者共享、真实模型学习质量及三类真实改进案例仍待完成；论文复现已按第九批使用者决定搁置。详见[学习流程与 API](eTraderBot-learning-api.md)。

## 第五批：Bot 模板与内部工作区

- “新建 Bot”提供中长期交易、现货交易、风控、复盘四种模板以及通用 Bot；角色和默认指令由共享契约与后端持久化。模板创建不触发模型介绍或自动授予业务权限，重试使用同一个创建键。
- Web/桌面保留 Bot 侧栏，在当前 Bot 内切换聊天、交易／风险检查／交易复盘和学习。独立账号菜单的交易入口已移除，旧 `/app/trading` 返回 Bot 列表。
- 当前 Bot 可创建或连接对应业务范围；创建范围、角色绑定和默认每日学习计划在同一事务完成。模板阶段不匹配时不留下半配置记录，风控／复盘不能通过重新绑定升级为交易角色。
- 多个角色 Bot 可连接同一范围；学习页只显示当前 Bot 的计划、运行及报告。断开连接暂停对应计划，后端继续检查 Bot 的绑定和交易权限。人工批准仍按已分配的使用者资格执行，未向 Bot 开放的人工审批范围有明确提示。
- 移动端增加原生模板选择页，从 Bot 资料进入交易与学习；复杂业务配置、资料上传和完整证据仍通过 Web 完成。已补 iOS 模板截图目录流程，本机未运行原生模拟器。
- 中英切换覆盖模板和工作区；模板 Bot 的外观选项折叠显示，390px 下可直接看到创建操作。[Spec](../specs/eTraderBot-v1-spec.md) 已同步信息架构、角色边界和新增故事 65–68。
- 本批验证：63 项 PostgreSQL 交易集成、83 项单元／契约／导航／截图目录检查、5 个 Chromium 场景通过；复核 contracts、core、db、API、Web、mobile 类型检查以及 Web 构建。浏览器覆盖四模板创建、阶段选择、共享范围、自动学习计划、聊天往返、刷新、交易批准／限额拒绝／模拟回执、学习资料与中英切换。人工分权的后端回归沿用交易集成，新的跨账户页面未单独进行浏览器验收；真实模型、Electron 和原生设备未运行。

## 第六批：业务范围工作区与接口配置

- 左侧固定业务范围选择器，支持新建、切换及按账号／Space 记忆选择；“+”菜单增加新建业务范围。四模板 Bot 在所选范围下创建，自动绑定适用交易阶段并建立每日学习计划。
- 同一业务范围聚合同业务 Bots 和接口；具体交易阶段及其算法批准、授权、资料和审计保持独立。已有场景通过第六项增量迁移归组，未改写原交易证据。旧 createDesk API 继续兼容并自动建立归组记录。

- 接口设置支持多个 HTTP 数据 API（行情、预测、持仓资产、规则等）、执行／回执接口以及已有 MCP 连接。HTTP 支持 GET／POST、查询参数、请求体和三种密钥位置；使用已有加密 SecretStore，API 不回显密钥，编辑支持保留密钥和修订号冲突检查。
- **配置管理已实现；外部读取与执行未接通。** 状态明确为“已配置 · 未验证连通”。配置不触发外部请求、Bot MCP 工具分配或交易授权；当前内部计算与模拟执行仍使用合成数据。真实 API 接入需要后续适配、字段映射与联调。

## 第八批：业务范围与 Space 合并

本批替代第六／七批的双层分组与多业务 Bot 规则。

- 业务范围直接复用 Space，统一创建、选择、成员与数据隔离；新增业务创建在同一事务中完成 Space、成员、默认记忆和交易配置。旧空 Space 可配置后继续使用。
- 一个 Bot 固定属于一个业务范围，普通 Bot 和群聊同样在业务内管理；模板创建自动连接本业务的适用场景。“全部 Bots”汇总导航，打开其他业务 Bot 时切换实际 RPC 上下文。
- 标签以 Space 归属生成；重命名使用同一 Space 名称。接口凭据、学习资料、批准与额度不随汇总视图或模板复用跨业务传播。
- 新迁移保持单业务旧 Space 的 ID 和历史证据；若旧 Space 内存在多套配置，整笔迁移拒绝，要求明确历史分配，禁止自动重写加密内容或合并批准。
- Web／桌面删除重复的私人空间创建入口；原生端统一业务命名并自动采用当前业务创建 Bot，未配置的业务明确提示先在 Web 完成交易字段及数据 API 配置。
- 更新 Spec 故事 76、领域术语、API 文档和 ADR 0002。
- 本批验证：70 项 PostgreSQL 交易／迁移测试、17 项行级权限回归、116 项契约及 Web／移动交互回归通过。13 个 Chromium 场景覆盖已有业务就地配置、四模板与通用 Bot、跨业务切换、汇总标签、接口隔离、共享范围、改名、删除、IME 输入、中英文、390px 窄屏，以及既有交易／学习批准流程。
- contracts、db、API、Web、mobile 类型检查通过；Expo 依赖检查使用离线模式，未将其当作联网兼容性验证。Web 生产构建通过，保留既有大 chunk 提示。
- 本地分支数据库在完整备份后应用第七项迁移；迁移前后内容与交易表摘要一致。当前开发页可访问，创建菜单只有一个业务范围入口，无页面异常。截图在忽略目录 `test-report/business-spaces-preview/`。
- 未执行完整仓库 CI、Electron、原生设备或真实外部数据／模型联调。旧版同时运行时仍尝试向同一 Space 新增第二套配置的写入会被唯一约束拒绝；本地升级已完成，不把该行为宣称为旧双层模型的兼容支持。
