## 行为

- 负责人状态只由服务端判定：任务的服务端阻塞含 `assignee:archived` / `assignee:missing`、未设置负责人，或负责人不在当前有效 Bot 列表时，页面读取 `businessCycle.recovery`。列表缺项只触发查询，不再直接显示“已归档”。服务端说负责人有效，即使不在列表中也不显示归档或恢复控件。
- 显示：摘要行“负责人名（已归档）”或“未分配”；任务内“负责人已归档：名称”或“无负责人”。阻塞行中的 `assignee:archived` / `assignee:missing` 显示为“负责人已归档”/“无负责人”，证据阻塞键保持原样。
- 更换：只列 `candidates`，通过原 `tickets.update` 提交，身份确认流程不变；`canReplace=true` 但没有候选时显示“暂无符合该专业的 Bot”且不能提交。提交中按钮禁用防重复。服务端拒绝在该任务旁显示：`FORBIDDEN`（含 `data.reason`）→“此 Bot 不能接手该任务”，`NOT_FOUND` →“此 Bot 已不可用”，401 → 05 的“你已无权访问此业务”，其他走通用错误；不显示服务端原文，随界面语言切换，所选替代者保留。
- 刷新：订阅现有看板工单变动通知，收到即刷新业务周期（含恢复资料）；周期 5 秒轮询和恢复资料 5 秒轮询仍作兜底。订阅/重连循环从 `Board.tsx` 抽为共用 `lib/board-events.ts`，看板行为不变。
- 保留：恢复沿用原工单与周期，已有结果、未解决事项、引用继续显示；缺前序证据时更换后仍显示阻塞。05 按业务保存的草稿及原版本冲突处理不变。
- 文案：新增 8 条（zh-CN/zh-TW 已翻译）；原负责人下拉的 `Assignee` 文案不再使用，提取时移除。
