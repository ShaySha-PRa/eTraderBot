# eTraderBot 第一版实施计划

状态：业务选择 Q1–Q10、整体方案及 spec 已获使用者确认，2026-11-03 开始实施。第 1–3 节记录确认范围，其余章节约定工程与验收方案。代码进度与已执行验证见 [实施记录](../implementation/eTraderBot-v1-progress.md)；本计划描述的完整第一版尚未全部交付。

## 1. 交付目标

在现有 eTraderBot / Rakazo 壳上交付电力交易协作能力。第一版包含数据接入、三类业务决策、风控、人工批准、范围授权、模拟执行、复盘和自动学习的完整流程。使用者认可 Bot 后，可以在明确授权的范围内让它执行。

第一版采用模拟接口验收。真实数据与真实交易接口取得后单独联调；模拟通过不等于真实接口或算法实盘表现已验证。实施阶段是同一版本内部的工作顺序，学习与授权执行都属于第一版交付。

| 项目 | 已确认范围 |
| --- | --- |
| 主体 | 售电公司、发电企业、独立储能；三类都纳入，业务优先次序未限定 |
| 地区 | 上海、江苏（业务地点苏州）、山东；具体交易品种与规则按适用条件配置 |
| Bot 角色 | 延续原计划的中长期、现货、风控、复盘四角色；现货用不同技能和任务覆盖日前、日内、实时 |
| 学习来源 | 聊天讲解与反馈、上传文件、授权范围内的操作记录、历史数据；参考现有电力交易论文清单 |
| 学习频率 | 每个 Bot 每天自动触发，也能手动触发；创建 Bot 时可设每日时间，之后可通过对话修改 |
| 学习目标 | 交易员经验是基线；允许提出不同策略，展示依据与对比验证结果，由人决定是否启用 |
| 批准方式 | 逐笔批准与范围授权都支持，默认逐笔批准 |
| 审批分工 | 算法启用、交易授权为两项权限；同一人可兼任，也可分配给不同的人 |
| 数据共享 | 论文和通用知识可共享；业务原始数据与专有策略按主体、账户默认隔离，使用者明确选择共享经验 |

地区与主体是产品覆盖范围，不据此假定九种组合都具有相同的市场资格、品种与接口。

## 2. 三条业务验收主线

| 主体 | 业务任务 | 待建立的模拟输入契约 | 可检查的决策产物 |
| --- | --- | --- | --- |
| 售电公司 | 购电与合同组合、敞口分析、候选调整 | 需求预测、合同与持仓、报价或价格情景、约束 | 购电或合同调整候选、敞口变化及依据 |
| 发电企业 | 发电能力和成本约束下的量价申报 | 可发能力、成本、运行约束、价格情景 | 量价申报候选、约束检查结果 |
| 独立储能 | 电量和功率约束下的充放电与报价 | SOC、容量、效率、功率约束、价格情景 | 充放电计划与报价候选、状态轨迹和约束结果 |

这些输入是契约设计起点，不冒充已取得的公司字段字典。每类至少交付一个可执行、可重放的决策算法与一个学习改进案例，不能仅以文本建议或透传人工表完成验收。

三条主线均运行：读取有来源的数据 → 调用指定算法版本 → 生成候选 → 风控检查 → 逐笔批准或范围授权 → 模拟执行及回执 → 复盘 → 学习与候选改进。

影子运行只记录候选；模拟执行另产生模拟回执。二者在界面、记录与验证证据中明确区分。

## 3. 学习、版本与批准

### 3.1 学习过程

每日或手动触发 → 收集授权范围内的新资料 → 提炼经验与改进假设 → 形成技能或算法草稿 → 自动验证、回测或影子比较 → 展示报告 → 有权限的人批准启用。

允许形成与交易员不同的方案。草稿可以随时创建；复盘和验证门槛约束它能否成为待批准版本。旧计划中“复盘前不能开新版本”的限制不再阻止草稿生成。

### 3.2 两项独立批准

- 算法启用批准：允许某个有证据支持的算法版本用于真实交易。
- 交易批准或范围授权：允许对指定业务对象执行某个操作，或在明确条件下持续执行。

算法启用不自动授予交易权。范围授权绑定算法版本，新版本不会继承旧版本的授权。风控 Bot 可以检查、解释、反对和升级，不能自批。通用工具的“始终允许”不能替代交易授权。

### 3.3 范围授权

授权记录包括主体、账户或资产、市场和业务、算法版本、有效期、单笔限额、累计限额、审批人及撤销状态。每次提交均重新校验。超范围、过期或已撤销时停止新增提交。

限额来自适用业务规则或有权限的人工配置，不能由 Bot 因为学习结果而自行放宽。

## 4. 工程方案

### 4.1 复用壳，补齐交易领域

复用现有 Bot、会话、群组协作、技能、routine、Task/Run、认证身份和审批卡。现有 routine 支持时区与手动运行，可承载学习触发。

建议在同仓共享包实现交易契约与领域逻辑，通过现有 MCP 集成暴露交易工具；应用服务负责组合与可信身份传递。部署形态保持可调整，不另建替代壳的调度或编排引擎。

MCP 是工具接入方式。授权、数据来源、算法版本和额度检查都在交易服务执行，不能依赖技能文本、模型自报身份或模型自报“已批准”。同一现货 Bot 的不同业务场景应绑定服务端可验证的场景与权限，不能只在提示词中写工具限制。

| 能力 | 责任 |
| --- | --- |
| 业务上下文与数据接口 | 主体、账户、资产、地区、业务与来源；行情、预测、持仓、敞口等统一契约；模拟与真实适配器共用契约 |
| 算法登记与运行 | 保存不可覆盖的版本、输入输出要求、适用范围、产物及依赖摘要；固定版本运行并保存输入快照 |
| 学习与验证 | 接收四类学习资料，形成经验或候选代码/参数，执行回放与约束验证，保留比较证据 |
| 风控与交易授权 | 校验资格、审批、版本、额度、期限和撤销状态；记录准入或拒绝原因 |
| 执行与对账 | 模拟提交、状态与回执；真实适配器接入点；请求去重与状态核对 |
| 审计与共享 | 关联资料、学习、版本、决策、批准和执行；按主体和账户控制读取、派生经验与共享 |

共享行为放入 packages，平台只负责相应交互。Web 与桌面复用界面；移动端共享同一后端契约。依赖本机录屏的学习资料需通过具备该能力的端采集，其他端可以查看和使用已授权记录。

### 4.2 建议的数据与版本约定

- 决策和验证记录绑定主体/账户、市场/业务、规则版本、算法版本、输入快照、时间范围、来源及运行环境；LLM 可以解释结果，数值由数据接口与算法运行产生。
- 算法版本最少区分草稿、待批准、已批准、已退役；验证任务另记未完成、通过、失败或证据不足，不能将没有结果视为通过。
- 已批准版本固定代码、参数、模型产物及必要运行配置。任何影响交易决策的技能修改也纳入版本与批准边界，不能借普通技能编辑绕过它。
- 回测、影子、模拟执行与真实执行分别标识。真实执行入口只接受对应环境的权限、来源与适用规则；模拟批准不能直接用于真实提交。
- 通用经验与业务经验分别保存；派生经验继承来源的访问边界。共享具体内容时记录范围与操作人，不能因“总结过”而自动扩大读取权限。

### 4.3 每日任务与失败处理建议

- 每个 Bot 保存时间与时区，创建时设置，授权使用者可以通过对话修改；修改后反馈新的安排和下次触发时间。
- 同一 Bot、学习输入范围和验证配置的重复请求复用正在运行的任务；新资料可形成后续任务。使用现有持久化任务与数据库认领，避免跨 Bot 的全局串行。
- 服务停机时无法执行定时学习；恢复后合并补一次遗漏窗口，并展示实际执行时间。学习失败保留失败原因，允许重试，不改变已批准策略。
- 没有新增资料或没有充分改进证据时，可以只形成学习报告，不强制生成或发布新版本。每日学习不等于每日重训所有模型。
- 缺少必要输入、数据过期、规则未配置或关键校验失败时，阻止新增交易提交并请求处理。
- 提交超时先核对同一请求的状态，不能直接重复下单。已提交操作继续跟踪；撤销授权不冒充撤销已成交交易，撤单本身按独立操作处理。
- 累计额度校验与占用需原子执行；按明确回执核销或释放占用。并发请求不能各自看到旧额度后同时放行。
- 保留已批准旧版本供选择或回退；切换版本仍需满足相应授权。学习任务不能自行改变正在使用的版本。

以上为使已确认要求可执行而提出的工程约定，随整体计划一起确认；不增加新的业务目标。

## 5. 算法研究与验证标准

论文清单是研究输入，不等于已有约 100 个可调用算法。先按三条已确认业务主线选择可实现方法，每类建立明确的基线、契约和测试数据；论文提出的方法经核查、适配与复现后再进入候选版本。

已抽查的四篇论文及适用边界见[讨论记录](eTraderBot-plan-discussion.md#首批论文调查证据)：发电侧和储能有对应候选，售电公司的直接对应资料仍需补充。实施第一步完成候选方法的资料核查，不预设一定每天训练 DDPG 或 PPO。

建议的验证门槛：

1. **能运行且可重放**：输入输出、单位、时区与约束明确；固定数据、版本与必要随机种子可重放，数值误差有明确容差。
2. **约束有效**：非法输入、缺失数据和越界输出有确定处理；验证报告中的硬约束失败不能被收益指标抵消。
3. **比较有效**：使用相同数据窗口和适用规则比较候选与人工经验/既有算法；训练、调参和评价数据分开，检查未来信息泄漏。
4. **证据可解释**：记录基线、目标、风险与成本指标、失效场景、样本范围和结论；资料不足时标记证据不足。
5. **批准可追溯**：审批人看到确定版本与确定报告；产物、参数、评价数据或规则改变后，旧证据不能默认为覆盖变化。

第一版硬验收针对流程、约束、可重放性、权限和证据完整性。合成数据的收益数字只作为测试结果，不承诺真实盈利或所有市场的适用性。具体业务指标、权重和门槛随业务配置记录，未经设定不能声称“优于人工”。

生成代码和训练/验证在受限运行环境执行，不提供真实交易写权限或生产凭据。自然语言经验的意义与证据质量使用明确、版本化的评价标准；不以关键词匹配代替语义评判。模型评价独立报告错误和成本。

## 6. 实施里程碑

以下 M0–M5 都属于第一版，不将学习、批准或执行留作未来占位。

| 阶段 | 主要工作 | 阶段完成证据 |
| --- | --- | --- |
| M0：业务契约与算法准备 | 三主体与地区配置；数据、候选、授权、回执契约；合成数据；核查三类基线与论文候选 | 三类带明确来源的测试数据；缺失接口明确报错；每类有可实现算法说明、约束与评价目标 |
| M1：算法运行与模拟交易 | 版本登记、输入快照、受限运行、影子记录、模拟执行和状态核对 | 三类各有一个可运行且可重放算法；结果、模拟回执与来源完整关联 |
| M2：风控与两种批准 | 风控检查、算法启用权限、逐笔批准、范围授权、额度占用、撤销和拒绝审计 | 同范围可执行，篡改参数/版本、越权、过期、并发超额和撤销后提交均被拒绝 |
| M3：Bot 与交互接线 | 四角色、现货三个业务场景、MCP 工具权限、创建时学习设置、对话修改、审批交互 | 三类业务可从 Bot 会话跑完整流程；场景限制由服务端执行；相应端可查看状态和完成有权限的操作 |
| M4：自动学习闭环 | 四类来源、每日与手动触发、经验提炼、候选代码/参数、验证比较、启用批准、资料隔离及显式共享 | 每类至少一个改进案例；无证据不启用；每天或手动均能触发；没有批准不能改变交易策略 |
| M5：综合验收与接入文档 | 三条完整业务流程、异常恢复、审计回放、跨端检查、安装配置与真实接口接入说明 | 验收矩阵全部有结果；记录未连接的真实接口；第一版可在模拟环境复现 |

M0 的算法研究可以与通用契约工作并行；先让一条流程贯通，再复用到其余主体。第一版完成条件仍要求三条主线全部过线，不以先完成的一条代替另外两条。

## 7. 综合验收矩阵

| ID | 场景 | 通过标准 |
| --- | --- | --- |
| V01 | 三类完整业务流程 | 各自完成读数、决策、风控、批准/授权、模拟执行、复盘、候选学习；不是同一储能示例改名称 |
| V02 | 来源与数值 | 无接口、缺必要字段、过期数据有明确结果；不由 LLM 补造交易数值；模拟来源全程可见 |
| V03 | 版本和重放 | 固定输入与版本可重放；修改产物产生新版本；输入、算法、规则与结果可追溯 |
| V04 | 逐笔批准 | 未批准、错误审批人、修改意图后复用批准均被拒绝；重试同一提交不产生重复交易 |
| V05 | 范围授权 | 主体/账户/资产、业务、市场、版本、期限、单笔和累计限制均生效；并发提交不突破额度 |
| V06 | 撤销与状态不确定 | 撤销或过期后停止新增提交；已提交仍能查状态；提交超时不会盲目重发 |
| V07 | 算法与交易分权 | 算法启用不自动放行交易；风控文字、普通工具批准或技能更新都不能绕过交易授权 |
| V08 | 每日及手动学习 | 创建 Bot 设置时间和时区；对话修改后生效；定时、手动、重复触发与停机恢复行为符合约定 |
| V09 | 四类学习入口 | 聊天、文件、已授权操作记录、历史数据均能纳入一次学习并追溯来源；不默认为录制用户所有操作 |
| V10 | 学习与版本演进 | 三类各有候选改进证据；允许与人工不同；验证失败或证据不足保留草稿；人批前不改变实盘可用版本 |
| V11 | 资料隔离与共享 | 不同主体/账户不能读取对方业务原始资料或派生专有策略；显式共享只开放所选范围 |
| V12 | 评价可靠性 | 数据切分、基线和约束记录完整；无评价结果不能显示通过；合成收益不被标记为真实收益 |
| V13 | 模拟与真实隔离 | 模拟数据、模拟批准和模拟回执不能冒充真实系统凭据、授权或成交 |
| V14 | 角色、场景与平台 | 四角色职责生效；现货保持一个角色；服务端约束场景工具；Web/桌面及适用移动交互完成检查，原生采集限制明确 |

常规测试使用可重放合成数据，离线验证契约、权限和算法效果。真实模型的学习端到端检查需要使用者配置的模型连接，费用与结果单独报告；离线伪模型通过不能代替真实模型检查。

## 8. 外部依赖与完成边界

| 依赖 | 当前状态 | 处理方式 |
| --- | --- | --- |
| 模型连接 | 沿用产品已有设置，由使用者配置 | 可运行无需模型的离线测试；实际自动学习需可用模型，不在仓库保存密钥 |
| 公司字段与接口 | 当前检查范围未取得真实契约、样例和交易连接器 | 第一版用明确来源的模拟契约；真实资料取得后补适配与一致性测试 |
| 真实市场规则 | 本轮未核实地区/主体的具体资格、参数与品种 | 使用标识为测试用途的规则版本；真实接入前逐项核实适用性 |
| 历史与示范数据 | 尚未取得真实业务验证集 | 合成数据验证工程流程；真实效果评估单独建立合规授权的数据集 |
| 论文复现 | 抽查四篇，尚未运行论文代码或证实对应开源实现 | M0 核查方法与复现条件；明确记录改编与原论文之间的差别 |
| 持续运行环境 | 每日任务需要 API、任务执行与数据库服务运行 | 本地部署说明写明服务依赖及停机补跑；浏览器关闭不应取消已保存计划 |
