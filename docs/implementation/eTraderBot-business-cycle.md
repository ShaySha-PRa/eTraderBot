# 模拟业务周期：合同、申报、计量与结算

本批基于 `feat/etraderbot-v1`、`998c6bae`，以实际代码为准实现课程审查后的模拟闭环。没有替换 Rakazo Agent 框架，没有新增调度器。本批不提交、不推送；原课程审查稿及天气接入保留。

## 交付范围

一个交易业务内的主管和四类专业 Bot 读取同一份结构化证据。周期依次具备合同组合、预测及资产状态、申报回执、模拟正式出清、履约、实际计量、模拟账单、内部结算试算和有来源的复盘结果。这里的业务先后关系不是四个 Bot 的固定执行顺序。

| 能力 | 实现与边界 |
| --- | --- |
| 合同与持仓 | 每时段电量、价格、结算参考点、金融／物理属性；关联预测、出清、计量和偏差。金融合同不占用物理可用电量；物理合同与其他物理承诺共同检查可用量。 |
| 模拟市场规则 | 固定 `P25-synthetic-v1`，包含主体、阶段模式、窗口、修改／撤销条件、前序证据。中长期／日前可报量报价，日内／实时仅接收结果；创建后 1 小时关闸，禁止重复改报及撤销。以上全是教学配置，不代表省级现行规则。 |
| 交易控制 | 原准备／执行／撤单服务共同检查周期与规则。已配置周期的业务不得用未关联的旧分析绕过规则。Bot 生成候选前要求对应场景、参数和代码产物的算法已获人工批准；人工可先试算、准备并审核算法，试算本身不授予执行权。执行仍独立检查算法启用和交易逐笔批准／范围授权。 |
| 证据版本 | 来源、源记录号、状态、来源类别、时段、规则版本、引用、内容摘要及记录人可追溯。相同源记录与内容幂等，冲突拒绝；更正必须指向最新版本并追加，旧证据不可覆盖。 |
| 结算核对 | 固定点数计算双偏差与等价差价，按合同／日前偏差／实时偏差分项，与模拟账单核对。缺成本／其他费用时净利润为空。未确认计量或缺账单时仅有暂估，不能完成复盘。 |
| 按需协作 | 四种结构化任务分别映射必要角色。前序任务与确认资料不足时阻塞，资料就绪后通过原 Ticket → Task/Run 通知唤醒；不同角色的独立任务可分别入队。 |
| 复盘结果 | 记录引用版本、摘要、分歧、未解决事项及未启用的改进提案。更新源证据使下游旧试算／复盘失效并重新阻塞或待办，旧结果仍可查。 |

主管进入业务时作为默认会话，直接专业会话与“全部 Bots”导航保留。主管读证据、派单及查看进度，没有交易角色，不能代替人工批准或代专业 Bot 完成有据结果。风控与复盘不准备或执行交易；普通 Bot 不获得周期读取或写入权限。原精确资料只读授权也不自动扩大到整个周期。

专业结果的自然语言质量没有用关键词打分。后端只验证身份、版本引用、结构字段、任务依赖和业务状态；模型是否正确理解任务、充分解释分歧，仍需真实模型的独立效果评价。

## 操作入口与演示

Web 入口 `/app`，Electron 使用同一页面。选一个**模拟发电或售电业务**，在其中创建中长期、现货、风控、复盘模板各一个；主管自动存在。首次演示建议使用单独的模拟业务，以免改变已有业务的申报入口要求。

1. 在主管的“业务周期”页点击“载入 P25 模拟”。载入合同 100 MWh、300 元/MWh，金融属性，预测 90 MWh、320 元/MWh，以及可用电量 90 MWh。展开证据查看来源和完整结构。
2. 任务选择“合同覆盖”，点击“只派给所需角色”。只生成中长期任务。另派“结算复盘”，此时显示阻塞，缺少出清／履约／计量／账单／结算等证据。
3. 进入现货 Bot 的“业务周期”（主管页有快捷入口）。点击“基于共享证据分析”，候选电量为 90 MWh；100 MWh 金融合约没有直接扣减成物理占用。
4. 点击“准备交易意图”。人工分别“批准算法”和“批准交易”，之后才能“提交模拟申报”。每个批准仍使用既有审批人及身份确认。仅批准其中一个不能执行。
5. 点击“导入模拟出清与履约”。写入日前 90 MWh、320 元/MWh，实时 80 MWh、310 元/MWh和履约证据；与实际持久化的申报／执行 ID 关联。执行回执不冒充出清或计量。
6. 实际电量保持 80，状态选择“已确认”，点击“导入模拟计量”。可先选暂估观察完成证据缺口；随后追加确认版本。模拟账单与计量引用一起记录。满足启动条件时可以先调查，未解决事项保留为 review，不能仅因已开始调查就完成复盘。
7. 点击“核对结算”。双偏差 `100×300 + (90−100)×320 + (80−90)×310 = 23700`；等价差价 `80×310 + 90×(320−310) + 100×(300−320) = 23700`。界面显示分项 30000、−3200、−3100 元、账单差额 0、净利润未建立。
8. 展开“结算复盘”任务，填写“人工记录结果”、分歧、未解决事项和可选改进提案，再记录有据结果。这是明确标识的人工演示记录，不冒充模型输出；未解决事项不为空时停留在待复核状态。
9. 在主管页查看专业结果、来源及阻塞项。需要依赖关系时，派新任务前选择已有前序任务；前序尚未完成的新任务不会入队。无依赖任务不等待无关角色。
10. 将实际电量改成 82，点击“追加计量更正”。旧 80 MWh 计量、23700 元试算及原复盘仍在历史中；旧复盘失效。再次“核对结算”得到 24320 元，复盘重新待办。重复核对不增加账目。
11. 查看“证据历史”，核对来源、版本、`supersedesId` 和引用。风控／复盘页面不显示交易按钮；后端同样拒绝其交易写入，改界面或绕行普通任务接口不能放行。

教学周期覆盖下一 UTC 日的首个小时，同业务同一时段重复载入返回原周期，不重置规则窗口或清除历史。关闸后不能重新申报；可创建独立模拟业务重新演示。该限制是后端规则检查的一部分。

移动端从 Bot 资料页或主管总览进入“业务周期”，可以只读查看规则、阶段证据、结算、任务和历史；导入与本周期人工交易操作在 Web 完成。移动聊天使用同一共享工具及权限检查。原生交互尚未设备验证。

RPC 使用既有认证、工作区和身份确认机制：`businessCycle.list/get/createDemo/importEvidence/demoResults/demoMetering/analyze/settle/assign/complete`。共享 Bot 工具为 `business_cycle`，仅暴露 `list/read/assign/analyze/settle/complete`；Bot 身份取自持久化运行，不接受参数伪造身份，不提供外部证据编造／导入操作。

`importEvidence` 为认证人类的结构化合成资料入口，支持合同、预测、资产、出清、履约、计量和账单。`cycleId + source + sourceRecordId` 保证去重；更正携带 `supersedesId`。这不是公开无认证推送 API，也没有接入真实正式账单。既有天气 API 独立保留，不会自动映射为负荷或出力预测。

## 迁移与兼容

新增迁移 `20261128120000_business_cycle`，只增加四张周期／证据／分析关联／任务关联表及 RLS、不可变更新触发器，没有搬运旧聊天、记忆、Bot 或交易证据。旧数据库副本先迁移验证，再对已备份的本地分支库应用同一迁移；28 张原有表（20 张交易表及 Bot、聊天、消息、事件、记忆、任务、运行相关表）的完整行指纹保持一致。运行身份的 RLS 授权另通过现有迁移 CLI 更新，未改 `.env`。

未创建周期的业务继续原流程。创建周期后，新的准备／执行需使用该周期关联的分析；不能靠旧独立试算绕过阶段检查。原订单继续读取、核对与保留历史。周期规则和证据均追加留存，不猜测历史资料归属。

## 验证与未交付部分

最终命令、通过数量及回归边界见[验收记录](eTraderBot-v1-acceptance.md#模拟业务周期验收2026-11-05)。单元与隔离数据库验证计算、角色、RLS、幂等、更正和任务入队；浏览器验证真实 RPC 和页面操作，测试中的人工结果不等于真实模型成果。

本批只交付发电／售电身份下的教学电能量闭环。储能缺 SOC、效率及轨迹证据时拒绝周期分析；其原独立基线未删除。跨业务共享资产承诺汇总、多品种费用／税费／利润模型、真实出清／计量／正式账单接入、三省全部规则、辅助服务交易、固定版本经验交接、算法插件市场、论文复现和独立训练仍未交付。未验证真实模型的任务拆解／协作／总结质量，未运行 Electron E2E、iOS/Android 原生设备或全仓 CI，也未声称策略收益和实盘可用。
